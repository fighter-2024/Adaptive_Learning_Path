# 项目实现时间表

> 团队 5 人：2 客户端前端 + 2 后台前端 & UI + 1 后端 | 共 16 周

---

## Phase 0 · 讨论 & 设计（第 1-2 周）

| 任务 | 负责人 | 交付物 |
|------|--------|--------|
| 功能范围最终确认 | 全员 | 功能清单 |
| 知识图谱学科范围确定 | 全员 | 课程名称 + 知识点大纲 |
| UI 原型设计 | 2 人（UI & 后台组） | 两套前端的线框图 / 设计稿 |
| API 契约文档 | 后端 + 各前端各 1 人 | 接口文档（路径 / 入参 / 返回） |
| 数据库表设计 | 后端 | ER 图 + 建表 SQL |

---

## Phase 1 · 基础环境（第 3-4 周）

| 任务 | 负责人 | 交付物 |
|------|--------|--------|
| Neo4j + SQL Server 环境搭建 | 后端 | 数据库就绪 |
| FastAPI 项目骨架 + 全局响应模型 | 后端 | `server/` 能跑，`/health` 返回 OK |
| admin/ 项目初始化（Vue 3 + Vite） | UI & 后台组 | 空项目能跑，路由框架搭好 |
| frontend/ 项目初始化（UniApp） | 客户端组 | H5 + 小程序空项目能编译 |
| 知识图谱数据准备 & 导入脚本 | 后端 | 第一批知识点导入 Neo4j |

---

## Phase 2 · 核心功能（第 5-9 周）

### 后端（1 人）

| 周次 | 任务 |
|------|------|
| 第 5 周 | 知识图谱 CRUD API + 题库管理 API |
| 第 6 周 | DINA 认知诊断 service（Q矩阵 + EM + 后验推断） |
| 第 7 周 | 路径规划 service（拓扑排序 + 贪心推荐） |
| 第 8 周 | 学生数据 API + 社交基础 API |
| 第 9 周 | AI 接入（诊断解读 + 错题归因） |

### 客户端前端（2 人）

| 周次 | 任务 |
|------|------|
| 第 5 周 | 登录 / 注册、首页框架 |
| 第 6 周 | 学习路径展示页 |
| 第 7 周 | 知识点学习页 + 答题页 |
| 第 8 周 | 诊断结果页 + 错题归因展示 |
| 第 9 周 | 学习周报页 + 社交排行榜 |

### 后台前端（2 人）

| 周次 | 任务 |
|------|------|
| 第 5 周 | 登录 + 仪表盘首页 |
| 第 6 周 | 知识图谱管理页 + 题库管理页 |
| 第 7 周 | 学生数据看板 |
| 第 8 周 | 社交内容管理页 |
| 第 9 周 | AI 诊断与周报页 + 系统配置页 |

---

## Phase 3 · 高级功能（第 10-13 周）

| 任务 | 负责人 |
|------|--------|
| 社交激励完整功能（打卡 / 好友 / 成就） | 后端 + 客户端前端 |
| 路径推荐理由 AI 解释 | 后端 |
| 学习周报 AI 生成 + 定时任务 | 后端 + 全部前端 |
| 管理后台数据统计图表 | 后台前端 |
| 性能优化（图谱查询 / API 响应速度） | 后端 |
| 小程序端适配 & 微信审核准备 | 客户端前端 |

---

## Phase 4 · 测试 & 收尾（第 14-16 周）

| 周次 | 任务 |
|------|------|
| 第 14 周 | 前后端联调、Bug 修复 |
| 第 15 周 | 用户测试、体验优化 |
| 第 16 周 | 文档整理、答辩材料准备、部署上线 |

---

## 关键节点

```
第 2 周末   ✓   UI 设计稿 + API 文档定稿
第 4 周末   ✓   两端前端 + 后端都能独立跑起来
第 9 周末   ✓   核心功能闭环（学员能走完"诊断→学习→答题→看结果"）
第 13 周末  ✓   全部功能完成，进入测试
第 16 周末  ✓   项目交付
```
