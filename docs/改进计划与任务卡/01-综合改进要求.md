# 01 · 综合改进要求

## 1. 总体成功标准

系统应从“后端接口和页面骨架”升级为“真实数据贯通、图谱可探索、诊断可解释、构建可重复”的项目。所有改进按 P0、P1、P2 分级：

- **P0**：缺失会导致核心演示不真实、不安全或不可运行。
- **P1**：直接体现自适应学习主题，缺失会使项目竞争力不足。
- **P2**：体验、性能和工程质量增强，不阻塞最小闭环。

## 2. 学生端改进

### 2.1 认证和请求基础（P0）

- API base URL 必须通过环境配置或统一配置模块提供，不得写死 `localhost`。
- Token 获取、持久化、启动恢复、过期清理和退出登录必须贯通。
- 学生页面必须区分未登录、加载中、空数据、业务错误和网络错误。
- 删除 CommonJS `require` 等不适用于当前 Vite/UniApp 构建的动态取 Token 方式。
- 页面不得通过空 catch 静默忽略关键接口失败。

### 2.2 真实答题闭环（P0）

- 题目和选项来自服务端学生取题接口，学生端不保存正确答案。
- 单选、多选、判断三类题型使用同一数据契约；多选答案必须规范化排序。
- 判题、解析、答题记录、Q 矩阵关联和掌握度变化全部由服务端完成。
- 支持逐题提交和一组题批量提交；重复点击必须防止重复请求。
- 提交成功后刷新知识点状态、诊断入口和路径数据。

### 2.3 图谱与路径呈现（P0/P1）

学生端提供三个一级视图：

1. **我的学习路径（默认）**：有向步骤图，突出当前节点、下一步、已掌握和锁定节点。
2. **课程图谱**：`课程 → 章节 → 知识点` 的可折叠树图。
3. **关系探索**：以选中知识点为中心的 1～2 层局部关系网。

明确不在首版实现智慧树“环图”。全量网图只能作为高级视图，不能成为学生端默认首页。

图谱交互要求：

- 拖动画布、缩放、复位、适应视图；
- 图例、搜索、按掌握状态筛选；
- 点击节点后就地高亮前置和后继关系；
- 打开详情卡片，显示掌握概率、难度、预计时间、推荐理由和学习入口；
- 章节和子图按需加载，首屏默认不超过 80 个可见节点；
- 右下角缩略导航只在节点较多时显示；
- 颜色表达掌握状态，形状表达节点类型，不能一套颜色同时表达两种语义。

建议状态：

| 状态 | 含义 | 建议视觉 |
|---|---|---|
| mastered | 掌握概率 ≥ 0.8 | 绿色 |
| learning | 0.4 ≤ 掌握概率 < 0.8 | 蓝色 |
| weak | 掌握概率 < 0.4 | 橙色/红色 |
| not_started | 无数据 | 浅灰色 |
| locked | 前置条件未满足 | 灰色虚线/锁图标，作为独立布尔状态 |

### 2.4 诊断、解释和周报（P1）

- 诊断页展示掌握度、上次诊断时间和数据不足原因。
- AI 解读必须有规则降级内容；LLM 失败不能使页面不可用。
- 周报统计来自真实答题记录和掌握变化，不得用前端模拟。
- AI 回答中关联的知识点必须能跳转到知识点详情。

## 3. 管理端改进

### 3.1 核心页面（P0/P1）

- 所有菜单页移除纯占位内容。
- 仪表盘展示学生、题目、知识点、活跃度和最近诊断的真实统计。
- 知识图谱管理页同时提供章节树、知识点表格和图谱画布；编辑操作仍以表单为主，图谱用于关系理解和选择。
- 题库页完成筛选、分页、编辑、Q 矩阵关联和批量导入结果展示。
- 学生数据页展示掌握度、诊断记录和答题时间线。

### 3.2 管理端图谱（P1）

- 支持章节筛选、知识点搜索、节点聚焦和前置/后继高亮。
- 前置关系编辑复用现有全量替换接口，保存前进行环检测或展示服务端环路错误。
- 删除节点前必须展示依赖影响；不得通过前端绕过服务端约束。
- 首版不要求持久化画布坐标，布局由前端计算。

## 4. 后端 API 和服务改进

### 4.1 新增读取接口（P0）

- 新增学生取题接口，返回题目和选项但不返回答案、解析。
- 新增学生图谱接口，统一返回 `nodes + edges + meta`。
- 新增节点邻居接口，用于树图和关系网懒加载。
- 新增管理端完整图谱读取接口，供管理画布使用。
- 所有新增接口必须先写入 `docs/改进计划与任务卡/API契约文档-v2.md`。

### 4.2 认证与错误处理（P0）

- 个性化读取接口必须明确要求学生 Token；不得在 Token 丢失时静默返回匿名结果。
- 数据库、图数据库和 LLM 异常统一转换为可读业务错误并记录日志。
- 关键写接口应具备幂等或重复提交保护。
- 前端和后端都不得吞掉导致数据不一致的异常。

### 4.3 查询与性能（P1）

- 图谱查询必须支持 `focus_id`、`depth`、`max_nodes`，避免默认全图加载。
- DINA 诊断只读取当前用户和必要范围的数据，不得每次扫描无关用户的全部答题记录。
- 图查询和 SQL 查询避免 N+1；必要时批量查询。
- 返回被截断时必须在 `meta.truncated` 中明确告知前端。

## 5. DINA 诊断改进

### 5.1 正确性（P0）

- 明确重复作答聚合策略：最近一次、时间衰减或全记录似然三选一，并写入文档和测试。
- 禁止使用以 `question_id` 为键的普通字典无说明覆盖历史作答。
- 在线单题掌握度更新与完整 EM 诊断的 slip/guess 参数来源必须一致或明确区分。
- 无 Q 矩阵、记录不足、题目参数异常时返回明确原因。
- 掌握向量的知识点顺序必须稳定并可追踪。

### 5.2 性能与可复现（P1）

- EM 参数、收敛阈值和最大迭代从配置读取。
- 保存诊断所用参数版本、记录时间范围和算法版本。
- 增加重复作答、稀疏 Q 矩阵、全对、全错、未收敛等测试。

## 6. 学习路径算法改进

### 6.1 可配置（P1）

- 距目标距离、掌握度、难度、预计时间等权重移入配置，不在 service 中散落常量。
- 保存或返回本次推荐使用的权重版本。
- 权重必须有范围校验，并提供默认值。

### 6.2 可解释（P1）

- 每一步返回结构化 `reason_codes` 或 `score_components`，同时保留面向学生的中文 `reason`。
- 推荐结果必须满足前置拓扑；检测到环路时拒绝生成并提示管理员修复。
- SQL Server 掌握数据读取失败时不得静默伪装为“全部未学习”；应返回降级标记或业务错误。

## 7. AI 功能改进

- 诊断解读、路径解释、知识点答疑、周报全部经过统一 LLM service。
- Prompt 集中管理；输入做长度限制，输出做非空和结构校验。
- 设置超时、有限重试和规则降级，不阻塞核心学习流程。
- 不向模型传输密码、Token、数据库连接信息或不必要的个人信息。
- 周报同一学生同一周可缓存，数据变化时定义失效策略。

## 8. 数据库、配置与安全

- 为 SQL Server 提供版本化迁移脚本，而不是依赖会 DROP 数据的初始化脚本升级生产数据。
- 对能够在同一数据库内约束的字段建立真实主键、唯一约束、索引和外键；跨 Neo4j/SQL Server 的 ID 通过应用层校验和一致性检查脚本保证。
- 生产环境检测到默认 JWT Secret 时必须拒绝启动；开发环境可明确警告。
- `.env.example` 只含占位值；仓库不得提交真实凭证。
- 配置页面不得回显完整 API Key，更新时使用掩码和“留空不修改”语义。

## 9. 工程化与质量

### 9.1 必须项（P0/P1）

- 根目录 README 写清架构、环境、启动顺序、数据初始化、测试和构建命令。
- 后端、管理端、H5、微信小程序都必须可重复构建。
- CI 至少执行后端测试、管理端构建、H5 构建；条件允许时加入小程序构建。
- 新接口必须有 service 和 router 测试；核心页面必须至少提供可复现的人工验收路径。
- 消除新增警告；已有 Sass 和大包体积警告记录为技术债并逐步处理。

### 9.2 基线命令

```powershell
cd server
python -m pytest tests -q -p no:cacheprovider

cd ../admin
npm run build

cd ../frontend
npm run build:h5
npm run build:mp-weixin
```

任何任务若使已有测试或构建从通过变为失败，默认不予验收。
