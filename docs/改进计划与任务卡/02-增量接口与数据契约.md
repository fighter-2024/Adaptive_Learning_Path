# 02 · 增量接口与数据契约

> 本文件保留改进方案形成过程，便于追溯。现行正式契约为 `API契约文档-v2.md`；若两者不一致，以 V2 为准。执行 M2、M3、M5、M6 时，必须先修改 V2，再开始编码。

## 1. 学生取题接口

### GET `/api/student/questions`

用途：替换学生端硬编码题目，为逐题和批量答题提供安全数据。

参数：

| 参数 | 类型 | 必填 | 约束 |
|---|---|:---:|---|
| knowledge_point_id | string | 是 | 已存在的知识点 ID |
| count | int | 否 | 默认 10，1～50 |
| exclude_done | bool | 否 | 默认 false |
| type | string | 否 | single_choice / multi_choice / true_false |

响应示例：

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": "q_001",
        "content": "题干",
        "type": "single_choice",
        "difficulty": 0.3,
        "options": [
          {"label": "A", "content": "选项 A"},
          {"label": "B", "content": "选项 B"}
        ]
      }
    ],
    "total": 1
  },
  "message": ""
}
```

安全要求：

- 响应不得包含 `answer`、`correct_answer`、`explanation`。
- 下线题目、无 Q 矩阵题目默认不进入学生题目列表。
- 只有提交答案后，`submit-answer` / `submit-batch` 才能返回答案和解析。

## 2. 学生图谱接口

### GET `/api/student/graph`

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|:---:|---|
| view | string | 否 | tree / network / personalized，默认 personalized |
| focus_id | string | 否 | 聚焦知识点 |
| depth | int | 否 | 默认 2，范围 0～3 |
| max_nodes | int | 否 | 默认 80，范围 1～500 |
| include_mastered | bool | 否 | 默认 true |

响应：

```json
{
  "code": 0,
  "data": {
    "nodes": [
      {
        "id": "kp_001",
        "label": "一元一次方程",
        "node_type": "knowledge_point",
        "chapter_id": "ch_01",
        "difficulty": 0.3,
        "estimated_time": 25,
        "mastery_probability": 0.62,
        "status": "learning",
        "locked": false,
        "recommend_order": 2,
        "reason": "后续目标的前置知识",
        "tags": ["重点"]
      }
    ],
    "edges": [
      {
        "id": "pre_kp_001_kp_002",
        "source": "kp_001",
        "target": "kp_002",
        "relation": "prerequisite",
        "directed": true,
        "recommended": true
      }
    ],
    "meta": {
      "view": "personalized",
      "focus_id": "kp_001",
      "total_nodes": 22,
      "returned_nodes": 22,
      "truncated": false,
      "anonymous": false,
      "layout_hint": "dagre"
    }
  },
  "message": ""
}
```

字段约束：

- `node_type`：`course` / `chapter` / `knowledge_point`。
- `status`：`mastered` / `learning` / `weak` / `not_started`。
- `locked` 为独立布尔字段，不新增为 mastery status。
- `relation`：`belongs_to` / `prerequisite` / `recommended_next` / `related`。
- `mastery_probability` 无数据时为 null。
- `recommend_order` 不在推荐路径中时为 null。
- 课程根节点可以由 service 生成虚拟节点，不强制写入 Neo4j。

### GET `/api/student/graph/{id}/neighbors`

用途：节点点击后懒加载局部关系。

参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| direction | string | both | incoming / outgoing / both |
| depth | int | 1 | 范围 1～2 |
| max_nodes | int | 30 | 范围 1～100 |

响应沿用 `nodes + edges + meta`，并在 `meta` 中返回是否截断。

## 3. 管理端图谱接口

### GET `/api/admin/graph`

参数支持 `chapter_id`、`keyword`、`depth`、`max_nodes`。响应沿用图谱结构，但不返回学生掌握状态和推荐顺序。

首版关系编辑继续使用现有接口：

```http
POST /api/admin/knowledge-points/{id}/prerequisites
```

首版不新增节点位置保存接口；节点坐标由前端布局计算。

## 4. 学习路径响应扩展

在不破坏现有字段的前提下，`steps[]` 可增加：

```json
{
  "status": "learning",
  "locked": false,
  "reason_codes": ["LOW_MASTERY", "TARGET_PREREQUISITE"],
  "score_components": {
    "mastery": 0.38,
    "target_distance": 0.25,
    "difficulty": 0.18,
    "time_cost": 0.10,
    "total": 0.91
  }
}
```

`score_components` 面向调试和可解释展示，不得包含内部异常、SQL 或敏感配置。

响应 `meta` 建议补充：

```json
{
  "algorithm_version": "greedy-v1",
  "weight_profile": "default-v1",
  "degraded": false,
  "degraded_reason": null
}
```

## 5. 诊断可追踪字段

诊断会话应能够追踪：

- `algorithm_version`；
- `parameter_version`；
- `answer_count`；
- `answer_time_from` / `answer_time_to`；
- `converged`；
- `iterations`；
- 重复作答聚合策略。

若暂不修改数据库表，至少将这些字段记录到结构化日志，并在后续迁移中补齐。

## 6. 兼容与错误规则

- 新字段优先采用向后兼容的可选字段，禁止无过渡删除现有字段。
- 参数校验错误继续使用 Pydantic 和统一错误响应。
- 个性化接口缺少有效学生身份时返回 401；不得标记 `anonymous=false` 后返回匿名数据。
- Neo4j 查询被 `max_nodes` 截断不算错误，但必须返回 `truncated=true`。
- 数据源异常不得返回 code 0 的空数组伪装成功。
