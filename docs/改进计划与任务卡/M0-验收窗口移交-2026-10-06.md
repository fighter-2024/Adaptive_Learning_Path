配置与故障排查经验：

- 当前 Settings 来源优先级是“显式初始化参数 > `server/.env` > 进程环境变量 > 文件 secrets”。已定义在 `.env` 的键不能靠临时 `$env:...` 覆盖；测试故障应使用隔离配置，避免误伤现有服务。
- SQL Server 采用集成认证，无需索取 SQL 登录密码；`SECRET_KEY` 是应用 JWT 签名密钥，与 SQL 认证是两回事。
- 最新修复记录是 [SQL Server 连接反复失效根因与修复](../Delivery/2026-10-05-SQLServer连接反复失效根因与修复.md)：此前环境变量覆盖 `.env` 导致 TLS 信任失败，现已固定来源优先级；记录还说明受控机器证书已完成配置。新的环境应核对实际有效配置，避免直接照抄旧故障结论。
- 旧验收也出现过启动进程无法取得 Windows 集成身份而登录失败。健康/认证异常时检查有效配置、运行身份和日志，再决定是否重启；不要要求用户改为 SQL 密码认证。
- Neo4j `store_lock` 错误常见于对同一 data 目录启动了第二个实例。先查监听、进程和日志；不要删锁文件、批量结束 Java 进程或清空数据库。

### 8.1 站点访问被"已保存的权限设置"阻断：根因、边界与解除路径（2026-10-06 复核）

**移交更正：**本节既有机制分析保留用于历史追溯，不代表 M01 已独立确认完整根因。M01 后续只读核对两个 origin 均 `access=allow`，负责人实测其他窗口可访问；本窗重启仍失败。不得据工具错误推定负责人曾拒绝、所有窗口均禁止本机访问，或再次要求修改已允许的规则。当前操作边界与新窗口接手方式以 [新移交第 7 节](M01-移交新M0验收-2026-10-06.md#7-浏览器异常的准确边界)为准，不通过换地址/工具绕过策略。

M6 真实截图链此前因浏览器站点访问被拒绝而未完成。经复核（只读排查，未改任何权限配置、未换主机名/端口/浏览器绕过），该阻断的准确归属与机制如下，后续窗口按此识别，不要重复误诊：

- 原文报错对应 `persisted_user_denied`，消息 `A saved user permission setting blocks this action.`，`decisionSource: "user_persisted_setting"`，`retryable: false`；定义位置：in-app browser 服务 `%ProgramFiles%\WindowsApps\OpenAI.Codex_*\app\resources\cua_node\bin\node_modules\@oai\browser-desktop\scripts\browser-service.mjs`。
- **不是** Chromium 站点内容设置，**不是**企业策略，**不是**外置 Chrome/Edge 扩展问题：两套服务的专有键不同（in-app browser 用 `iab_history_approval_mode`，外置扩展用 `history_approval_mode`），该报错只在 in-app browser 服务里定义；两个浏览器的 profile 存储与扩展 Local Extension Settings 中均无站点黑名单记录。
- 机制：in-app browser 站点访问询问文案为 `Allow <browserName> to access <origin>?`，带两个持久化档位——`session` → `scope: "conversation"`，`always` → `scope: "global"`。命中拒绝后每次动作以 `requireSavedPermissions: true` 复核，返回 `{decision:"deny", scope:"global", source:"browser-use-persisted-state"}`，**不再弹窗、直接失败**。因此"重试同一地址"必然复现同一句报错，放开终端/文件权限也不影响它。
- 边界（不要尝试）：该全局记录只经 Codex 应用进程的命名管道读写（`Va = t => t === "win32" ? "\\\\.\\pipe\\codex-browser-use" : "/tmp/codex-browser-use"`），**不落任何可读文件**（`~/.codex` 下的状态文件里查无 `origins`/`approval_mode` 记录），所以终端无法检查或修改；`origins` 判定会把同一主机的端口归一化到同一条 origin 记录，`127.0.0.1:8080` 与 `127.0.0.1:3000` 共用该判断，换端口/主机名属于绕过且无效。
- 解除路径（须在 Codex 内操作）：① 在内置浏览器再次访问站点，若弹出询问则选**始终允许**；② 若不弹出，说明该 origin 被存为 global 拒绝，需在 Codex 界面撤销该条记录，或换新会话重新触发询问后再按需放行；③ 撤销后同时复核 `http://127.0.0.1:8080/` 与 `http://127.0.0.1:3000/`。
- 合规备选：若 Codex 站点权限一时无法解除，可用人工实操页面并留存截图，再由验收窗口用只读 SQL/Neo4j 抽查仪表盘统计与学生详情数值做对照（仪表盘数字 ↔ 查询结果一一核对）。规则禁止的是用直接 URL/API 造成功数据冒充点击链路，不禁止人工实操留证。
