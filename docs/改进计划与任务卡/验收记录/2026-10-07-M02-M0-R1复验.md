## 新增 P2：冷启动/账号切换的统计认证结果错误

没有保存 Token 的正常登录窗口，A 的 `/auth/login` 和 `/auth/me` 成功；我的页仍有正确 A 身份，但两页统计提示“当前登录状态无效”，点击重试无效。刷新后恢复。A退出→未登录导航回登录页→B正式登录又复现；B刷新后才恢复自己的统计。

根因是 `frontend/src/store/user.js` 的 initializationPromise 赋值时序：无 Token 分支没有 await，异步 IIFE 在外部赋值前同步完成，内部 finally 置 null 后又被外部赋回已完成 false Promise。后续 initializeSession/ensureAuthenticated 复用旧 false；新页面新增的真实读取依赖这一方法，因此暴露了该问题。

受控客户端行为复现直接载入当前方法源码，替换 Vue/Pinia/HTTP 为最小状态与正式登录响应形状：初始无 Token **false**，login 后 **isLoggedIn=true**，ensureAuthenticated(false) 仍 **false**。此处为受控客户端生命周期验证，不冒称真实 HTTP；真实页面与服务器日志提供独立佐证。没有修改 user.js。

截图：[冷登录首页失败](../../Delivery/2026-10-07-M02-M0-R1-cold-login-error.png)、[正确身份但统计失败](../../Delivery/2026-10-07-M02-M0-R1-cold-mine-error.png)、[B 切换失败](../../Delivery/2026-10-07-M02-M0-R1-b-switch-error.png)。不能把“刷新后能显示”覆盖“正常登录后不能显示”。剩余返修仅客户端会话 Promise 生命周期及必要行为门禁，不触及后端鉴权规则。
