## 2. 需返修的两项

### P1 · 他人 student_id 参数没有按契约拒绝

[V2 第 5 节](../API契约文档-v2.md#5-权限矩阵)要求：“任何通过参数传入其他 student_id 的学生请求均返回 40101。”

使用正式登录的学生 B，传入学生 A 的 ID，独立实测如下：

| 接口 | 传入位置 | 实际 HTTP / code | 预期 |
|---|---|---|---|
| POST `/api/student/diagnosis/explain` | query | 200 / 0 | 拒绝，40101 |
| POST `/api/student/chat` | query | 200 / 0 | 拒绝，40101 |
| POST `/api/student/chat/knowledge-point` | query | 200 / 0 | 拒绝，40101 |
| GET `/api/student/weekly-report` | query | 200 / 0 | 拒绝，40101 |
| POST `/api/student/diagnosis/explain` | JSON body | 200 / 0 | 拒绝，40101 |
| POST `/api/student/chat` | JSON body | 422 / 40000 | 拒绝，40101 |
| POST `/api/student/chat/knowledge-point` | JSON body | 422 / 40000 | 拒绝，40101 |

`server/app/routers/student/ai.py` 的四个接口未检查 query 的 `student_id`；诊断接口不读取 body，聊天模型的 extra-forbid 将身份参数变成普通输入校验错误。身份仍取当前学生，B 的诊断/周报为空，没有读到 A 的数据，因此**本次没有证据表明发生跨学生数据泄露**；缺陷是显式身份越界请求未按冻结契约拒绝。

证据：[独立 HTTP JSON](../../Delivery/2026-10-06-M02-M9-http-evidence.json)的 `issues`、`spoof_student_id`、`cross_student_body_contract`，以及 10 月 7 日再次查询 B 的 `cache_boundaries.cross_day_spoof_still_code0_own_b_data`。只返修 M9 新增四个接口的身份参数门禁；不重下 M8-R2、不改全局 optional 鉴权。

### P2 · 有效时长不足一分钟被模型说成没有有效记录

A 经真实页面累计提交三次作答（两次正确、一次重复作答错误），SQL 中正值时长合计 **20 秒**，`questions_done=3`、`correct_rate=2/3`、`study_time_minutes=0`。分钟向下取整符合现有统计口径。

真实模型成功响应却写道：“其中已记录的作答时长为 0 分钟，说明本周的练习记录中未包含有效时长数据”。`degraded=false`，随后可作为正常报告缓存。已有有效正值记录，不能由取整后的 0 推断记录缺失；也不能将作答时长等同全部学习时长。

证据：同一 [HTTP JSON](../../Delivery/2026-10-06-M02-M9-http-evidence.json)的 `source_sql_after.answers` 与 `cache_boundaries.configuration_restored.ai_summary`；成功缓存超期再生成的 `success_expired_25h` 也出现同类文案。修复应把原始有效秒数及取整含义提供给总结，并对这个明确边界作事实校验/规则兜底，不改变统计口径或核心学习算法。
