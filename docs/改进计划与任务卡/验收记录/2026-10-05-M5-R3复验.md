## 1. 实现范围

- 新增独立 `StudentQuestionQuery`、`StudentQuestionItem` 和 `StudentQuestionList` 模型，与管理端 `QuestionDetail` 分离。
- 注册 `GET /api/student/questions`，强制 `require_student`；管理员或匿名请求不能取得学生题目。
- Neo4j 只读确认知识点存在；SQL Server 按 `q_matrix` 筛选启用题目，支持 `knowledge_point_id`、`count`、`exclude_done` 和 `type`。
- 学生响应只序列化 `id`、`content`、`type`、`difficulty`、`options`，不包含 `answer`、`correct_answer` 或 `explanation`。

## 3. 真实双库与 HTTP 联动

- 清洁环境重启 Uvicorn 后，`GET /health` 返回 HTTP 200，`status=ok`，`neo4j=true`、`sqlserver=true`；启动进程不携带 `SQLSERVER_*` 环境变量。
- 直接使用真实双库只读调用 `kp_001`，返回 2 道 Q 矩阵关联题；响应字段集合为 `content,difficulty,id,options,type`，未出现答案或解析字段。
- 本次独立复核使用受控既有管理员身份调用管理 API 创建两枚唯一临时知识点和一题，再通过真实 `/auth/register`、`/auth/login` 创建临时 student 并取题：知识点创建、题目创建、学生注册、学生登录和取题业务码均为 `0`；学生取到新建题目，包含 2 个选项，响应字段为 `id,content,type,difficulty,options`，`answer_or_explanation_exposed=false`。
- 同一真实联动中，管理员 Token 请求学生取题返回 HTTP `403`；题目改绑到第二枚知识点后，旧知识点取题 `total=0`，新知识点取到 1 题，证明 Q 矩阵筛选随管理端改绑同步。
- 验收结束按相反顺序通过管理 API 删除临时题目和知识点，并按唯一用户名精确删除临时学生账号；只读复核显示临时学生用户行数 0、临时题目查询 0、临时 Neo4j 知识点查询 0。未删除、清空或改写既有题目、Q 矩阵、Neo4j 图数据。
