## 2. P1 剩余：重复 query 只检查最后一个身份

四个路由以 `student_id: str | None = Query(...)` 接收单值；FastAPI 会选取重复 query 的最后一个值。`reject_foreign_student_ids` 只收到这个单值和 body，虽然注释提到重复参数，实际并未读取所有 query 值。

用正式学生 A 的 JWT，传 `?student_id=B&student_id=A`，body 为正常请求（未携带身份），独立真实 HTTP 结果：

| 路由 | 实际 HTTP/code | 预期 |
|---|---|---|
| POST `/api/student/diagnosis/explain` | 200/0 | 403/40101 |
| POST `/api/student/chat` | 200/0 | 403/40101 |
| POST `/api/student/chat/knowledge-point` | 200/0 | 403/40101 |
| GET `/api/student/weekly-report` | 200/0 | 403/40101 |

反向 `?student_id=A&student_id=B` 四条均 403/40101，说明拒绝受参数顺序影响。**没有读取 B 的个人数据证据**，但应拒绝的请求已进入自身业务/模型调用。原 R1 卡已明确“各渠道有冲突/重复参数时不能绕过”，属于该 P1 的剩余边界，不新增业务范围。

证据：[M02 HTTP JSON](../../Delivery/2026-10-07-M02-M9-R1-http-evidence.json)的 `repeated_query`，含参数顺序、路由、HTTP/code 与返回体。

## 3. P2 剩余：出现“秒”不代表总结符合事实

服务 `_contains_missing_duration_claim` 采用有限的连续子串判断，遗漏“暂无有效作答时长记录”“没有有效的作答时长记录”等表述；不足一分钟校验仅要求文本任意位置出现“秒”或“不足一分钟”，与已记录事实没有关联。

同一真实 SQL 样本有 **20 秒**有效作答。在独立 Python 进程中仅替换 provider HTTP 响应，保留真实 SQL 来源、缓存、`complete` 与 validator；每例先使本临时学生缓存失效，控制结果如下：

| 注入模型总结 | 应有结果 | 实际 |
|---|---|---|
| 本周未包含有效时长数据。 | 规则降级 | degraded=true，正确保留 20 秒/不足一分钟，通过 |
| 本周暂无有效作答时长记录；请在下周练习时每题预留20秒。 | 规则降级 | degraded=false，错误原文被保存为正常摘要 |
| 本周没有有效的作答时长记录。已记录20秒，不足1分钟。 | 规则降级 | degraded=false，内部矛盾原文被保存为正常摘要 |

第二例的“20 秒”是下周建议，不能证明已记录时长；第三例虽含正确事实，仍明确否定已有有效记录。应校验总结与原始事实的关系，不能只增加一个“秒”标记通过检查。以上为**受控模型边界注入**，不声称外部 provider 自然生成了这两段坏文案；首验曾有类似“暂无有效作答时长记录”的真实模型错误。

证据：同一 [HTTP JSON](../../Delivery/2026-10-07-M02-M9-R1-http-evidence.json)的 `controlled_summary_validation`，含注入文本、期待降级及真实服务返回。这里只是总结事实校验剩余缺口，真实统计口径未发现回归。
