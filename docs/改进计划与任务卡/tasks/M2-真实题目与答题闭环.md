# M2 · 真实题目与答题闭环

## 可直接下发指令

```text
执行 docs/改进计划与任务卡/tasks/M2-真实题目与答题闭环.md。
先阅读 docs/AI开发总则.md、docs/改进计划与任务卡/API契约文档-v2.md、00-范围与决策、02-增量接口与数据契约。
先更新 API契约文档-v2.md，再实现后端和学生端；完成后申请 M0 验收 M2。
```

## 目标

移除学生答题页的硬编码题目、正确答案和本地判题，打通“服务端取题 → 服务端判题 → 保存答题记录 → 更新掌握度”的真实闭环。

## 优先级与依赖

- 优先级：P0
- 前置依赖：M1
- 下游：M7、M8

## 必做范围

1. 将学生取题接口写入正式 API 契约并实现：
   `GET /api/student/questions?knowledge_point_id=...`。
2. 接口返回题目和选项，但不得返回正确答案和解析。
3. 支持单选、多选、判断三种题型；统一学生答案规范化规则。
4. 学生端答题页从知识点详情或路径节点接收 `knowledge_point_id`，请求真实题目。
5. 删除本地正确答案和本地判题逻辑。
6. 对接单题或批量提交接口，展示服务端返回的对错、解析和掌握度变化。
7. 防止重复点击导致同一答案重复提交；明确重做题目的记录策略。
8. 提交成功后刷新知识点和路径相关缓存/状态。
9. 补齐权限、题目不存在、无题、部分批量失败和数据库回滚测试。

## 不在范围

- 不重做 DINA EM 算法，交给 M7。
- 不新增题型。
- 不在学生端显示后台答案字段。

## 重点风险

- 题目详情和学生取题对象必须分离，避免 Pydantic 序列化误带答案。
- 批量提交中单题业务失败与数据库整体失败的语义必须符合正式契约。
- 多选答案比较必须消除顺序差异，但不能忽略重复或非法选项。

## 验收标准

- [x] 前端代码中不存在演示题 `q_001` 和硬编码正确答案。
- [x] 取题响应中的题目字段不含答案和解析。
- [x] 提交后 SQL Server 产生真实答题记录。
- [x] 返回的 `mastery_change` 与数据库结果一致。
- [x] 重复点击不会产生非预期重复记录。
- [x] 题目为空和接口失败都有明确页面状态。
- [x] 后端全量测试、H5 和小程序构建通过。

## 必须提交的证据

- 取题响应脱敏示例。
- 一次正确作答和一次错误作答的请求/响应。
- 作答前后掌握度及答题记录查询结果。
- 后端测试命令结果、H5/小程序构建结果、答题页截图。
