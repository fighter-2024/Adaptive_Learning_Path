# M6 · 管理端仪表盘与学生数据看板

## 可直接下发指令

```text
执行 docs/改进计划与任务卡/tasks/M6-管理端仪表盘与学生数据看板.md。
先阅读 docs/AI开发总则.md、docs/改进计划与任务卡/API契约文档-v2.md 和综合改进要求。需要新增接口时先改 V2 契约。
完成后使用真实学生作答和诊断数据申请 M0 验收 M6。
```

## 目标

完成管理端仪表盘、学生列表和学生详情，使管理员能够观察真实学习、答题和诊断数据。

## 优先级与依赖

- 优先级：P1
- 前置依赖：M1；完整验收依赖 M7
- 可与 M4、M8 并行

## 必做范围

1. 定稿并实现缺失的管理端统计和学生查询 API。
2. 仪表盘展示：学生总数、题目总数、知识点总数、本周活跃学生、最近诊断。
3. 学生列表支持分页、搜索和最近活跃时间。
4. 学生详情展示：
   - 基本信息；
   - 各知识点掌握概率；
   - 诊断会话摘要；
   - 答题历史时间线；
   - 当前推荐路径摘要。
5. 图表应兼容知识点较多的情况，默认展示薄弱项或分页，不强行绘制不可读的 500 轴雷达图。
6. 所有查询必须按管理员权限保护。

## 不在范围

- 不允许管理员直接修改学生掌握概率。
- 不实现学习小组、讨论区和好友关系。
- 不实现 AI 周报全文管理，交给 M9。

## 验收标准

- [ ] 仪表盘数据与数据库抽查一致。
- [ ] 学生列表分页、搜索和空状态正常。
- [ ] 学生详情只展示目标学生数据，无串号。
- [ ] 答题记录、掌握度和诊断时间能够相互对应。
- [ ] 大量知识点场景仍可读。
- [ ] 学生 Token 访问管理接口返回 403。
- [ ] 后端测试和管理端构建通过。

## 必须提交的证据

- 一名真实测试学生从作答到管理详情展示的完整截图链。
- 管理接口权限测试。
- 统计数字与 SQL/Neo4j 查询抽查对比。
