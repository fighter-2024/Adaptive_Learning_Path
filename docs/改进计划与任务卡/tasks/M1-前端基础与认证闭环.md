# M1 · 前端基础与认证闭环

## 可直接下发指令

```text
执行 docs/改进计划与任务卡/tasks/M1-前端基础与认证闭环.md。
先阅读 docs/AI开发总则.md、docs/改进计划与任务卡/API契约文档-v2.md、docs/改进计划与任务卡/00-范围与决策.md。
只完成本任务范围，完成后按任务卡格式申请 M0 验收，不要顺手实现其他任务。
```

## 目标

修复学生端和管理端的请求配置、Token 生命周期和路由保护，为后续真实联调建立稳定基础。

## 优先级与依赖

- 优先级：P0
- 前置依赖：无
- 下游：M2、M4、M6、M9

## 必做范围

1. 学生端 API 地址改为环境/构建配置，不得硬编码 `http://localhost:8000`。
2. 重构学生端 request 工具：
   - 使用 ESM/Pinia 可用方式读取 Token；
   - 自动附加 Bearer Token；
   - 统一解析业务 code；
   - 401 时清理登录态并跳转登录；
   - 网络错误和业务错误保留可展示信息。
3. 新增或完善学生登录/注册页面和路由入口。
4. App 启动时恢复 Token，并通过 `/auth/me` 校验；无效 Token 必须清理。
5. 完成退出登录流程。
6. 管理端 request、管理员 Token、401/403 和路由守卫做同等检查。
7. 为请求工具和关键认证逻辑补测试或最小可复现验证脚本。

## 不在范围

- 不实现社交登录、微信 OAuth、短信验证码。
- 不改 JWT 算法或用户表结构，除非发现阻塞性缺陷并先报 M0。
- 不实现业务页面内容。

## 交付物

- 环境配置示例和读取说明。
- 学生登录/注册/退出/恢复登录实现。
- 管理端管理员登录态和路由保护修复。
- 错误展示的统一调用方式。
- 更新后的启动说明或 README 片段。

## 验收标准

- [ ] API 地址切换无需修改源码。
- [ ] 登录成功后刷新 H5，用户仍为登录状态。
- [ ] 无效或过期 Token 会被清理并引导重新登录。
- [ ] 学生 Token 不能进入管理端受保护页。
- [ ] 管理员 Token 不能被学生端误当作学生身份。
- [ ] 请求失败不会被空 catch 静默吞掉。
- [ ] H5、微信小程序和管理端构建通过。
