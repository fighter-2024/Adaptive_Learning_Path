## 前置条件

- M1-R1 必须保证管理端路由能够真实加载页面。
- M3-R1 必须冻结 focus、截断、locked 和推荐语义。
- 可先修复页面代码，但没有以上两项通过证据时，M5-R1 不做最终通过判定。

## 退回原因

1. **P0：页面引用不存在的 `getRequestErrorInfo` 导出。**KnowledgeGraph 和 Questions 均无法在正常静态导入后完成模块加载。
2. **P1：知识点核心字段与前置关系采用两个请求保存。**第二个请求失败时第一个写入仍保留，界面却统一显示“保存失败”，造成半成功状态。
3. **P1：图谱未区分 course/chapter/knowledge_point 和 belongs_to/prerequisite。**所有节点、边样式相同，图例把结构关系误称为前置关系。
4. **P1：401、403 处理逻辑合并，保存操作缺少任务卡要求的二次确认。**
5. **证据缺失。**未提供真实 Neo4j/SQL Server CRUD、学生侧变化和逐行导入失败截图。

## 必须修复

### 请求与错误处理

- 统一决定请求错误辅助函数的正式接口：导出并测试 `getRequestErrorInfo`，或移除页面中的无效导入；不得保留两套错误解析。
- 401：清理过期登录态并进入登录页。
- 403：明确提示权限不足；不能与网络异常或普通 401 使用相同文案和状态。
- 业务错误、超时、断网、5xx 在页面上应有不同且可恢复的提示。

### 知识点原子保存

- 一次“保存知识点与前置关系”的用户操作不得出现不可识别的半成功状态。
- 优先提供一个 Neo4j 事务内完成节点字段和前置关系更新的原子后端操作。
- 如需给现有 POST/PUT 增加可选 `prerequisite_ids`，这是兼容性扩展，但必须先最小修改 V2 契约并保留原 prerequisites 接口。
- 若采用补偿事务，必须覆盖补偿失败，并向用户明确展示最终落库状态；仅 catch 后显示“保存失败”不合格。

### 图谱呈现

- course、chapter、knowledge_point 至少通过形状、尺寸、颜色或标签可靠区分。
- belongs_to、prerequisite 必须使用不同线型/颜色，并在图例中写明方向含义。
- focus 节点及直接前置/后继应分别高亮；截断时显示“正在展示局部图谱”或等价明确文案。
- 保留缩放、复位；布局应体现层级或拓扑关系，不得仅按数组顺序铺网格导致关系难以理解。
- 参考智慧树的是信息组织与交互，不复制其品牌、图标或受保护素材。

### 表单与确认

- 知识点和题目保存前展示变更摘要并二次确认，防止误覆盖关系和 Q 矩阵。
- 删除继续显示依赖影响和服务端真实拒绝原因。
- 题目选项、答案、题型变化保持一致；服务端校验失败时保留表单内容。
- 批量导入必须展示成功数、失败数、失败行号和逐行原因。

## 必须新增的验证

- 请求错误工具单元测试：401、403、业务码、超时、断网、500。
- 知识点与前置关系原子保存成功、环路失败、关系失败回滚测试。
- 图谱 node_type、relation、focus、truncated 的组件级或烟雾测试。
- 单选、多选、判断题创建和编辑测试。
- Q 矩阵更新失败时 SQL Server 事务回滚测试继续通过。
- 批量导入一成功一失败的结果渲染测试。

## 必须提交的真实证据

1. 新建知识点 A，再新建知识点 B 并把 A 设为 B 的前置；管理端刷新后关系存在，学生图谱同步变化。
2. 制造环路或非法前置关系，保存失败后证明知识点字段和关系均未半成功更新。
3. 新建题目并关联知识点；学生取题接口能看到题干和选项，但响应不含答案、解析。
4. 编辑题目关联知识点后，Q 矩阵同步变化。
5. 批量导入包含至少一条成功和一条失败，页面展示逐行失败详情。
6. 401、403、业务错误、断网四类界面截图。
7. course/chapter/knowledge_point 与 belongs_to/prerequisite 图例截图。
