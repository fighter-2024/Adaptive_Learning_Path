## P2：onLaunch的旧初始化结果仍导航B

App.vue的导航拦截器通过ensureAuthenticated(true)已有会话归属保护；onLaunch却直接initializeSession().then，false时根据**当时页面**跳登录页，没有确认该初始化仍属于当前会话。

实际链路反例：

1. 启动从存储恢复A Token，A /auth/me在途，启动回调等待。
2. 退出A，完成B登录；B通过实际导航拦截器进入首页。
3. A旧成功、HTTP401或业务40101返回。store正确将旧结果返回false，保留B身份/Token并抑制提示。
4. App的onLaunch回调仍reLaunch `/pages/auth/login`，干扰当前B导航。

B未被注销，登录页可能再转首页；旧导航副作用仍须消除。不要只因store保护通过或登录页会自恢复就宣告全链路通过。

要求启动完成后的导航只能处理所属会话；启动时捕获的身份/版本与恢复Token语义必须正确，或复用已验证的守卫并避免调用方再次无条件导航。不能只看isLoggedIn绕过当前Token真实校验。旧完成应无副作用；当前真实失败仍按正常路径处理。
