# M5-R3 · 学生正式取题前置补交卡

## 可直接下发指令

```text
执行 docs/改进计划与任务卡/tasks/M5-R3-学生正式取题前置补交卡.md。
保留 M5-R2 已通过的管理端页面、真实 CRUD、环路原子回滚、Q 矩阵、批量导入和图谱语义实现。只补齐 V2 契约中的正式学生取题接口及一条 M5→学生端真实联动证据，再申请 M0 复验：M5-R3。
```

## 背景与范围裁决

M5-R2 独立复验中，`GET /api/student/questions?knowledge_point_id=...` 返回 404。现有 `GET /api/student/knowledge-points/{id}` 只返回题目摘要，按契约不得包含选项，不能当作正式取题接口。

该能力原属于 M2。为避免任务互相覆盖，本卡只允许两种执行方式：

1. 先完成 M2 中正式学生取题接口的最小闭环，再回来补 M5 联动证据；或
2. 由同一执行者在本卡中实现该接口，但实现必须严格限定为 M2 已冻结的取题契约，不得顺带实现答题提交、掌握度更新或学生答题页。

## 必须完成

1. 实现并注册 `GET /api/student/questions`。
2. 支持契约参数：`knowledge_point_id`、`count`、`exclude_done`、`type`。
3. 返回 `id`、`content`、`type`、`difficulty`、`options`；禁止返回 `answer`、`correct_answer`、`explanation`。
4. 只返回通过 Q 矩阵关联到目标知识点的题目；知识点不存在、无题、非法类型和数量越界按 V2 契约返回。
5. 需要学生身份的数据行为必须使用有效 student Token；admin Token 不得被当作学生身份。
6. 不修改知识点详情摘要模型来夹带 `options`，正式取题对象与管理端题目详情对象必须分离。
7. 增加路由、service、序列化脱敏、Q 矩阵筛选、`exclude_done` 和权限测试，并跑后端全量测试。
8. 用管理端新建一题并关联临时知识点，学生取题接口读到题干和完整选项；响应全文确认不含答案/解析，随后精确清理临时数据。

## 禁止事项

- 不得把管理端 `QuestionDetail` 原样暴露给学生端。
- 不得在响应、日志、截图或交付文档中出现正确答案、解析、Token 或密码。
- 不得重写已通过的 M5 管理页面或改变既有管理接口。
- 不得把知识点详情中的题目摘要声称为正式取题成功。

## M0 通过条件

- 路由不再 404；真实关联题可取到 `options`。
- 学生响应不含任何答案/解析字段。
- Q 矩阵改绑后，旧知识点取不到该题，新知识点可以取到。
- 自动化、真实接口证据、清理证据齐全。
