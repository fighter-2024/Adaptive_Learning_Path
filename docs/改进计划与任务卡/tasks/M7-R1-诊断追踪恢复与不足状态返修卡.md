## 背景与范围

M7 首次验收的后端聚合、隔离、迁移、事务、测试和构建已通过。返修不得重写 DINA 算法、改变 `latest_attempt` 口径、删除历史 attempt，或顺带实现 M9 的 AI 解读。

本卡只处理三个已复现的 P1 缺陷：

1. 新诊断会话的 trace 无法通过 GET 恢复，POST 后又被页面二次加载清空；
2. 无有效答题记录时，页面主体不持久展示不足原因；
3. `mastery_probability` 被标成“正确率”，未开始项被显示成 0%。

## 必须完成

1. `GET /api/student/diagnosis` 查询 0002 的全部 trace 字段，并为新会话返回与 POST 完全一致的 `DiagnosisTrace`。
2. 旧会话必须继续兼容 `trace` 缺失。0002 已给旧行写入默认值，不能把默认 `converged=false/iterations=0` 冒充真实历史 trace；需要定义并测试可靠的“旧记录无 trace”判定。当前有效新诊断均有非空答题时间范围，可作为候选判定依据，但最终实现需在代码注释和测试中写清。
3. 页面 POST 成功后不得因随后的 GET 丢失或覆盖新 trace；刷新页面后仍能看到答题数、重复策略、收敛状态和迭代次数中的必要摘要。
4. 无最近诊断且全部知识点为 `not_started` 时，即使知识点列表非空，也要在页面主体持久显示“暂无有效答题记录”等原因和学习入口提示。
5. POST 返回 `40002` 后，页面应保留可见的不足原因，不能只显示短暂 Toast；重试、离开或成功诊断时再按明确规则清除。
6. 知识点详情把 `mastery_probability` 标为“掌握度”；`null` 显示“暂无数据”，不得显示“正确率 0%”。
7. 继续使用真实知识点名称、最近诊断时间和当前学生数据，不新增前端假数据。

## 必须补充的测试

- service/路由：新会话 GET 返回完整 trace，字段值与保存值一致。
- service/路由：0002 前的历史会话 GET 正常返回 alpha/time，且 `trace` 为空。
- service：另一学生的最近诊断不能被当前学生 GET 到。
- 页面可复现：成功诊断后 trace 立即可见，刷新后仍可见。
- 页面可复现：无作答学生在页面主体看到持久不足原因，点击重诊返回 40002 后仍可见。
- 页面可复现：未开始项显示“掌握度 暂无数据”，有数据项显示“掌握度 xx%”。
