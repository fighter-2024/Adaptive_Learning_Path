## P2：旧页面守卫仍导航新会话

实际 App.vue onShow 通过 ensureAuthenticated(true) 作路由守卫。实际模块反例：

1. A 的 ensureAuthenticated(true) 等待 /auth/me。
2. 退出 A，完成 B登录。
3. 返回 A旧成功、HTTP401或业务40101。
4. initializeSession正确返回false且B身份/Token保留；但 ensureAuthenticated仍 reLaunch `/pages/auth/login`。

这是守卫自己的副作用，request.js 已经隔离的注销/跳转不能保护它。登录页可能再转首页，不等于允许旧守卫触发路由跳转。

要求守卫完成后的导航/返回语义与它的所属会话一致；旧守卫不得导航当前 B。不能只检查 isLoggedIn 而绕过当前 Token 的 /auth/me 验证，也不能全局禁用未登录跳转。视需要重新验证当前会话或返回明确的过时结果，选择必须由真实调用链测试证明。

## P3：页面错误入口重新弹旧鉴权提示

实际登录页 catch 调用 showRequestError。A登录POST在途→B完成登录→A旧HTTP401/业务40101返回：请求封装已抑制其 notify，但 showRequestError看到 requestNotified为假，重新弹旧失败Toast。

要求旧鉴权错误携带有效的过时/已处理信息，并由统一错误展示入口尊重；身份、持久化、路由、提示均不干扰B。保留当前会话错误可见、避免重复提示，不得吞掉全部错误。补测旧成功导致 SESSION_STALE 的页面 catch、旧HTTP403/业务40100，以及所有相关错误入口。
