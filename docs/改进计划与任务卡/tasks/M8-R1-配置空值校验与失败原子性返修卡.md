## P1 缺陷

`SystemConfigUpdate` 允许 null；`update_system_config` 用 exclude_unset 保留显式 null。权重 float(None) 返回 500，其余字段在响应校验前写入 settings。PUT 返回 40000 后，GET 仍持续 500；混合请求中其他合法字段也已被修改。

证据及隔离复现脚本：`server/scripts/m01_verify_m8_config_null.py`。使用真实配置路由、独立进程，不触碰运行中服务或数据库。原 349 passed 不覆盖此缺陷。

## 必须完成

1. 区分“省略保持原值”和“显式 null”：对非空配置明确拒绝 null，并返回统一 40000 参数错误，不得返回未捕获 500。密钥空串/省略继续保持原值；如 null 也选择不修改，应在契约和测试中明确。
2. 在写入前校验整个候选配置（范围、类型、profile、四权重总和等），任何失败都不改变 settings，包括与非法字段同请求的合法字段。不能依赖响应模型校验作为写入后验证。
3. 测试覆盖全部可更新字段 null、空 profile、非法权重组合、合法+非法混合更新；对失败前后 GET/config snapshot 完整比较，并证明后续正常 GET、路径和诊断参数仍可用。
4. 保持安全回显，完整 API Key 不出现在响应、错误或日志；空密钥不覆盖原值。
5. 跑配置/路径专项与后端全量回归；管理端及学生双端构建如涉及前端也重跑。提交 Delivery 和结果。不得修复不相干业务、改已有账号或重启数据库。
