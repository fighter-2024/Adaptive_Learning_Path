## 目标

让项目具备安全配置、可升级数据库、自动化质量门禁和可重复部署文档，避免只能在开发者本机运行。

## 优先级与依赖

- 优先级：P0/P1
- 前置依赖：基础部分无；最终收口依赖 M1～M9
- 可与第一批任务并行，但最后一个完成验收

## 必做范围

### 数据库

- 新增版本化 SQL Server 迁移目录和命名规则。
- 将初始化脚本与增量迁移分开；迁移不得默认 DROP 已有数据。
- 为适合的 SQL 表补主键、唯一约束、索引和真实外键。
- 跨 Neo4j/SQL Server 的知识点 ID 提供一致性检查脚本或测试。
- 写清迁移执行、验证和恢复流程。

### 配置与安全

- 生产环境使用默认 JWT Secret 时拒绝启动。
- 检查 `.env.example` 完整性和仓库凭证泄露。
- 配置日志脱敏；API Key 不完整回显。
- 更新依赖和服务启动的最小安全说明。

### CI 与构建

- 建立自动化质量门禁，至少执行：后端测试、管理端构建、H5 构建。
- 条件允许时加入微信小程序构建。
- 构建失败必须阻止合并；缓存不得掩盖缺失依赖。
- 记录并逐步处理管理端大包和 Sass 废弃警告。

### 文档和部署

- 新建或完善根 README：架构、依赖、环境变量、启动顺序、数据导入、测试、构建、常见问题。
- 给出开发环境的一键或少步骤启动方式；Docker 化属于可选项，引入前需说明必要性。
- 更新 API 完成状态表，确保与真实实现一致。
- 汇总最终演示账号/数据准备方法，但不得提交真实密码。

## 不在范围

- 不执行破坏性 DROP/清库验证。
- 不自动部署到收费云服务。
- 不在仓库提交真实 `.env`、证书或数据库备份。
- 不以升级所有依赖为目标，避免无关大版本迁移。

## 验收标准

- [x] 空数据库可初始化，已有数据库可按版本增量升级。
- [x] 迁移失败有恢复说明且不会静默丢数据。
- [x] 默认生产 Secret 会阻止启动。
- [ ] CI 在任一测试/构建失败时失败。
- [x] 新成员按根 README 能完成启动、测试和构建。
- [x] 正式 API 状态表与代码一致。
- [x] 后端测试、管理端、H5、小程序构建全部通过。

## 必须提交的证据

- 空库初始化和非空库增量迁移记录。
- 默认 Secret 启动失败证据。
- CI 成功记录及一次故意失败的门禁证据。
- 按 README 从干净依赖环境执行的命令摘要。
- 凭证扫描或人工检查结果。
