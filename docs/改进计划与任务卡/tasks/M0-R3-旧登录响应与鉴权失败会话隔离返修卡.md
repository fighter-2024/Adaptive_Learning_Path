## P1：旧登录 POST 晚到会覆盖新身份或撤销退出

当前 login() 在 `await post('/auth/login')` **返回后**才增加 sessionVersion 和清空 initializationPromise，旧 POST 响应仍有权建立新版本：

- 发起 A 登录、暂缓其 POST 响应 → 完成 B 登录 → A 旧 POST 返回及 /auth/me 成功 → 最终变成 **A**，预期保持 B。
- 发起 A 登录、暂缓 POST → logout() → A 旧 POST 和 /auth/me 返回 → 最终 **logged_in=true/A**，预期保持退出。

这会使界面和后续请求采用已经被用户替换/撤销的身份。服务端仍按有效 JWT 鉴权，问题发生在客户端会话选择。

要求在登录尝试开始时建立生命周期标识，并在 POST 返回、写 Token、读用户、错误/完成分支检查该尝试是否仍有效；退出或后续登录使旧尝试失效。旧成功或旧失败都不能覆盖/清空当前身份，不得只对 /auth/me 的成功响应作保护。

## P2：旧请求 401/40101 会先在请求封装注销新账号

真实 request.js 的 HTTP401/403 和业务40100/40101 分支直接调用 clearStudentSession()，没有请求所属会话检查。user.js 的 catch 版本校验发生在该副作用之后：

- A 的初始化 /auth/me 在途 → 退出 A并完成 B 登录 → A 旧响应 HTTP401/40100 → B 被清空并跳登录页。
- 相同时序，旧响应 HTTP200/业务40101 → B 同样被清空。

要求发起请求时捕获所属会话，并在注销/跳转等副作用之前确认仍是该会话；旧响应允许作为旧请求的失败返回，但不得清除新 Token、用户、错误状态或触发新会话跳转。可增加客户端会话快照/匹配接口供请求封装使用，不改后端契约。当前会话自身的鉴权失效仍须处理；不能全局忽略401/403。
