## 必需证据

- [ ] 正常提交：仓库/分支/提交SHA、PR或运行链接，所有定义的检查完整成功，无跳过或吞错；记录实际检查名称、runner、测试及构建结果。
- [ ] 故意失败：在独立验证分支/临时PR隔离绕过App启动归属保护，保留静态标记；生产启动门禁在远端行为断言失败，后续quality检查失败。记录故障提交SHA、运行链接与相关日志。不得把故障合入默认分支。
- [ ] 合并阻断：核对该PR目标分支实际要求的检查/规则；故障检查失败时，普通合并入口确实被阻断。仅有红色CI或“不去点击合并”不构成此证据，管理员可绕过也不能冒充普通必需检查已生效。
- [ ] 精确恢复：恢复保护，提供恢复提交SHA、同一检查集全绿及对应PR可合并状态；保留故障与恢复两次运行证据，不能只覆盖旧失败记录。
- [ ] 清理：验证用故障没有留在最终提交，临时分支/PR状态及必要清理有记录；不改已验收业务算法、认证、统计或缓存。

可复用本地已证实的故障形状：在隔离App.vue中把启动归属检查条件旁路，生产verify:app-startup的真实链路矩阵会失败；恢复后通过。远端仍需重新实证。
