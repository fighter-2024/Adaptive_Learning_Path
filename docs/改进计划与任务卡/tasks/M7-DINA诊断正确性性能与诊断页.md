# M7 · DINA 诊断正确性、性能与诊断页

## 可直接下发指令

```text
执行 docs/改进计划与任务卡/tasks/M7-DINA诊断正确性性能与诊断页.md。
先阅读 docs/AI开发总则.md 中的 DINA 约束、docs/改进计划与任务卡/API契约文档-v2.md 和综合改进要求。
先写重复作答策略和测试，再改算法；完成后申请 M0 验收 M7。
```

## 目标

修复 DINA 诊断中重复作答被覆盖、查询范围过大和参数来源不一致的问题，并完成可用的学生诊断页。

## 优先级与依赖

- 优先级：P0/P1
- 前置依赖：M2
- 下游：M6、M8、M9

## 必做范围

1. 文档化重复作答聚合策略，并用测试锁定行为。
2. 删除无说明的 `question_id → 单条记录` 覆盖行为。
3. 诊断只查询当前学生、所需时间范围和必要字段。
4. 统一或明确区分在线更新与完整 EM 的 slip/guess 参数来源。
5. 记录收敛状态、迭代次数、参数/算法版本和答题范围。
6. 处理 Q 矩阵缺失、记录不足、全对、全错、未收敛和非法参数。
7. 学生诊断页展示掌握度、上次诊断时间、数据不足原因和重新诊断入口。
8. 诊断成功后刷新 mastery 和路径相关状态。

## 不在范围

- 不引入 scikit-learn、PyTorch 等 ML 框架。
- 不更换 DINA 为其他认知诊断模型。
- 不实现 AI 自然语言解读，交给 M9。

## 必测场景

- 同一题多次作答且答案变化。
- 稀疏 Q 矩阵。
- 全部答对、全部答错、只有一条记录。
- slip/guess 边界。
- EM 达到最大迭代仍未收敛。
- 两个学生数据严格隔离。

## 验收标准

- [x] 重复作答不会被偶然覆盖，策略有文档和测试。
- [x] 诊断查询不扫描无关用户全部答题记录。
- [x] 诊断结果可追踪到算法参数和记录范围。
- [x] 失败不会写入半完整诊断会话。
- [x] 页面展示真实 mastery，并能触发重新诊断。
- [x] 后端全量测试、H5 和小程序构建通过。

## 必须提交的证据

- 重复作答测试和预期说明。
- 优化前后查询范围或耗时对比。
- 一次成功诊断和一次记录不足诊断的接口及页面证据。

## 本次实现记录

- 重复作答策略固定为 `latest_attempt`：同一学生同一题按 `created_at` 最新
  的一次作为 DINA 观测，时间相同按 `answer_records.id` 较大者；历史
  attempt 仍保留并继续计入掌握度统计。
- 诊断答题查询限定 `WHERE user_id = ?`，只取 `id/question_id/is_correct/created_at`；
  掌握先验也限定为当前学生和当前 Q 矩阵属性。
- `diagnosis_sessions` 通过迁移 0002 保存算法版本、参数版本、答题时间范围、
  重复策略、EM 收敛状态和迭代次数；接口同时返回 `trace`。
- 交付证据见 `docs/Delivery/2026-10-05-M7-DINA诊断正确性性能与诊断页.md`。
