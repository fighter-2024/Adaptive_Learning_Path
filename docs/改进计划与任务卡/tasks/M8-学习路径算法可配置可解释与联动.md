# M8 · 学习路径算法可配置、可解释与联动

## 可直接下发指令

```text
执行 docs/改进计划与任务卡/tasks/M8-学习路径算法可配置可解释与联动.md。
先阅读 docs/AI开发总则.md、docs/改进计划与任务卡/API契约文档-v2.md、增量契约和综合改进要求。
保持拓扑约束，改进配置、降级语义和解释字段；完成后申请 M0 验收 M8。
```

## 目标

将学习路径从固定权重、静默降级的服务升级为参数可配置、结果可解释、失败可追踪的核心能力，并与学生端路径视图联动。

## 优先级与依赖

- 优先级：P1
- 前置依赖：M2、M7
- 下游：M9

## 必做范围

1. 把距目标距离、掌握度、难度、预计时间等权重移入配置。
2. 对权重范围和组合进行校验，定义默认 profile 和版本。
3. 路径响应增加向后兼容的 `reason_codes`、`score_components` 和 `meta`。
4. 确保任何推荐顺序都不违反 PREREQUISITE 拓扑。
5. 增加环路、目标不存在、全部已掌握、无掌握数据和数据库失败测试。
6. SQL Server 掌握数据失败时返回明确错误或 `degraded=true`，不得静默伪装为全部未学习。
7. 学生端展示推荐原因、掌握率和当前/下一步状态；完整 AI 解释仍使用现有解释接口或 M9 能力。
8. 若实现管理端参数配置，API Key 等敏感项不得回显完整值。

## 不在范围

- 不改变核心路线为未经验证的新算法。
- 不通过 LLM 直接决定路径顺序。
- 不实现图谱画布，交给 M4。

## 验收标准

- [x] 权重不再散落为 service 常量。
- [x] 默认权重下现有有效用例行为保持合理且测试通过。
- [x] 修改权重能够产生可解释的排序变化。
- [x] 每一步能够说明主要得分来源。
- [x] 图谱环路会阻止推荐并给出明确错误。
- [x] 数据源失败不会返回假个性化路径。
- [x] 后端全量测试通过。

## 必须提交的证据

- 两组权重配置及排序变化对比。
- `score_components` 响应示例。
- 拓扑合法性自动测试。
- 数据源失败和降级标记测试。
