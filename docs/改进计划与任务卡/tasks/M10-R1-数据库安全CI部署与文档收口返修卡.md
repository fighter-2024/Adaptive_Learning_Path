## 必须补齐

### 数据库迁移

在可丢弃的验收数据库或隔离副本中完成：

1. 空 SQL Server 数据库执行 `server/sql/init.sql`，记录表、主键、唯一约束、检查约束和示例数据结果。
2. 对已有数据的数据库执行 `python server/sql/migrate.py --dry-run` 和正式迁移，证明已有业务数据保留。
3. 在隔离副本中制造约束冲突，使当前迁移失败，证明事务回滚且 `schema_migrations` 不记录失败版本。
4. 重复执行迁移，证明已应用版本安全跳过。
5. 运行 `kg-data/scripts/verify_cross_store_ids.py`，分别记录通过和缺失 ID 的非零退出场景；脚本只能读取数据。

禁止通过 DROP、TRUNCATE 或清空正式数据获得证据。

### 安全

- 保留生产默认/短 JWT Secret 拒绝启动测试，并增加一次真实启动失败命令证据。
- 使用随机强 Secret 启动后端，证明可继续启动；证据中不得展示完整 Secret。
- 执行凭证扫描，人工复核 `.env.example`、日志、交付文档没有真实密码、Token、连接串和 API Key。
- 日志脱敏测试必须覆盖 Authorization、password、token、API key。

### CI 与构建

- 保存一次真实 CI 全绿记录，至少包含后端全量测试、管理端构建、H5、小程序构建和凭证扫描。
- 在临时分支或临时提交中故意让一个门禁命令返回非零，证明 CI 阻止通过；随后恢复，不把故障提交混入正式分支。
- 将 M1-R1 的“管理端业务路由烟雾测试”加入 CI，避免构建命令成功但页面未进入产物。
- 不关闭管理端大包和 Sass 警告；在文档中登记责任、风险和后续处理时机。
