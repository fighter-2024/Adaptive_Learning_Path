# 00 · 范围与决策

## 1. 本轮目标

本轮目标不是扩充演示数据规模，而是把现有后端能力、学生端和管理端连接成一个真实、可解释、可验收的自适应学习系统。

核心主题保持不变：

- Neo4j 表达章节、知识点和前置依赖；
- DINA 根据真实答题记录更新掌握状态；
- 路径算法依据图谱拓扑和掌握状态生成个性化学习路径；
- 前端以图谱和路径可视化方式向学生解释“现在学什么、为什么”；
- 管理端负责知识、题目、学生诊断和系统运行管理。

## 2. 已冻结的技术决策

- 后端：Python FastAPI。
- 关系数据库：SQL Server。
- 图数据库：Neo4j。
- 学生端：UniApp（Vue 3），目标平台 H5 + 微信小程序。
- 管理端：Vue 3 + Vite + Element Plus。
- 大模型：通过统一 LLM service 调用，不在页面或 router 内直接调用。
- API 响应继续使用 `{"code": 0, "data": ..., "message": ""}`。
- 新增依赖必须有必要性说明，并由 M0 验收；不得自行更换框架。

## 3. 本轮明确不处理

以下事项不作为 M1～M10 的阻塞条件，也不得被执行者擅自扩大为当前任务：

1. **申报书技术栈修改**：由项目负责人自行修改 proposal。
2. **学科和受众扩展**：当前继续使用现有初中数学演示数据。
3. **知识点扩展到 500 个以上**：数据扩充后续单独立项；本轮接口和页面需具备承载能力，但不负责造数。
4. **学习小组和讨论区**：当前产品范围不包含小组；不得按旧 proposal 恢复该模块。
5. **完整社交激励实现**：排行榜、打卡、成就按后续阶段推进，本轮不作为核心闭环验收条件。
6. **原样复制智慧树 UI**：只参考信息架构和交互方式，不复制品牌、素材和具体视觉资产。

## 4. 本轮必须遵守的产品原则

### 4.1 真实数据优先

- 前端不得硬编码题目、正确答案、掌握率或推荐路径来伪造闭环。
- 正确答案只由服务端判定；学生端取题接口不得下发答案和解析。
- 接口失败必须展示可理解的失败状态和重试入口，不得空 catch 后继续显示成功。

### 4.2 个性化优先

- 学生端默认回答“下一步学什么”，而不是默认展示一张全量关系网。
- 掌握状态、路径顺序和推荐原因必须来自当前登录学生的数据。
- 未登录或 Token 过期时，不得悄悄降级成匿名数据并冒充个性化结果。

### 4.3 可解释优先

- 推荐路径必须说明前置依赖、掌握度、难度或学习成本中至少一项依据。
- 图谱上的状态颜色、节点形状和边类型必须有图例。
- 算法参数、降级策略和数据缺失必须可追踪，不得静默吞错。

### 4.4 移动端可用优先

- H5/桌面可提供完整树图和局部关系网。
- 微信小程序首版展示推荐路径和局部子图，不要求一次绘制 500 个节点。
- 首屏默认限制节点数并采用按章节、按深度懒加载。

## 5. 范围变更规则

- 执行者发现需求与现有 API、数据模型或其他任务冲突时，记录事实、影响和候选方案，交 M0 决策。
- 未经 M0 确认，不得删除旧接口、修改公共响应结构、替换数据库或引入新前端框架。
- 扩展范围产生的新工作必须新增任务卡，不得隐藏在原任务中顺手实现。
