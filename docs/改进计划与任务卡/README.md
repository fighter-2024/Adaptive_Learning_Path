# Reasonix 综合改进计划与任务卡

> 本目录用于把项目审查结论转化为可下发、可验收的实施任务。
> **M0 为总控与验收窗口**：负责范围裁决、接口冲突协调、验收和回退；M1～M10 为执行任务。

## 1. 使用方式

1. 下发任务前，执行者必须完整阅读：
   - `docs/AI开发总则.md`
   - `docs/改进计划与任务卡/API契约文档-v2.md`
   - 本目录的 `00-范围与决策.md`
   - 自己领取的任务卡
2. 原则上一个会话只领取一张任务卡；并行开发时使用独立分支或 worktree。
3. 涉及接口变更时，必须先修改 `docs/改进计划与任务卡/API契约文档-v2.md`，再修改后端和前端。
4. 完成后按任务卡中的“交付回报格式”提交证据，不得只回复“已完成”。
5. 将交付结果发送给 M0，使用统一标题：`申请 M0 验收：M<number>`。
6. 只有 M0 明确给出“通过”后，该任务才算完成。

## 4. 推荐执行批次

当前 M1-R2、M2、M3-R2、M4-R1、M5-R2/M5-R3 已通过；M7-R1 原三个缺陷已关闭，但学习入口导航仍不可用，先完成 M7-R2 单项返修。因此后续按依赖顺序下发：

```text
已完成：M1-R2、M2、M3-R2、M4-R1、M5-R2/M5-R3
返修：M7-R2（不足状态学习入口 tabBar 导航；保留 R1 已通过项）
并行：M10-R2（数据库/安全/CI 收口）
M7-R2 复验、M7 最终通过后：M6 与 M8（按各自依赖推进，可并行）
最后：M9（依赖 M7+M8）
最终：M10 最终收口 → M0 全链路验收
```

若采用严格串行顺序，则为：`M7-R2 复验 → M6/M8 → M9 → M10 最终收口`；M10-R2 的本地收口可并行推进。

同一批次并行时，任何人不得自行改动其他任务的业务范围。发生接口或模型冲突时立即停止相关改动，由 M0 裁决后继续。

## 5. 最终完成定义

项目至少能够稳定演示以下真实闭环：

```text
登录
  → 查看课程图谱/个性化路径
  → 打开知识点
  → 获取服务端真实题目
  → 服务端判题并记录作答
  → 更新掌握度
  → 重新诊断
  → 推荐路径发生合理变化
  → 查看推荐原因或 AI 解读
```

管理端至少能够稳定完成：

```text
登录
  → 查看统计概览
  → 查询/编辑知识点与前置关系
  → 查询/编辑题目与 Q 矩阵关系
  → 查看学生掌握度、诊断和答题记录
```

“页面能打开”“使用硬编码数据演示”“接口失败后静默显示假成功”均不属于完成。
