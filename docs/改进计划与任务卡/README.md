# Reasonix 综合改进计划与任务卡

> 本目录用于把项目审查结论转化为可下发、可验收的实施任务。
> **M0 为总控与验收窗口**：负责范围裁决、接口冲突协调、验收和回退；M1～M10 为执行任务。

## 1. 使用方式

1. 下发任务前，执行者必须完整阅读：
   - `docs/AI开发总则.md`
   - `docs/改进计划与任务卡/API契约文档-v2.md`
   - 本目录的 `00-范围与决策.md`
   - 自己领取的任务卡
2. 原则上一个会话只领取一张任务卡；并行开发时使用独立分支或 worktree。
3. 涉及接口变更时，必须先修改 `docs/改进计划与任务卡/API契约文档-v2.md`，再修改后端和前端。
4. 完成后按任务卡中的“交付回报格式”提交证据，不得只回复“已完成”。
5. 将交付结果发送给 M0，使用统一标题：`申请 M0 验收：M<number>`。
6. 只有 M0 明确给出“通过”后，该任务才算完成。

已完成：M1-R2、M2、M3-R2、M4-R1、M5-R2/M5-R3、M6、M7-R3、M8（含R1/R2）、M9（含R1/R2/R3）

后续顺序为：`M10远端CI与合并阻断补证 → M0最终裁决`。本轮无既有依赖缓存安装和核心全链路已独立补验；M0-R1～R5本地剩余项全部关闭；远端CI成功、故意失败/恢复及合并阻断未齐前不宣布项目最终完成。收尾双库健康、七表残留 0，共享应用端口及隔离 8092/8093/8094 无监听；演示/复验使用加载当前源码的新进程。

同一批次并行时，任何人不得自行改动其他任务的业务范围。发生接口或模型冲突时立即停止相关改动，由 M0 裁决后继续。

## 5. 最终完成定义

项目至少能够稳定演示以下真实闭环：

```text
登录
  → 查看课程图谱/个性化路径
  → 打开知识点
  → 获取服务端真实题目
  → 服务端判题并记录作答
  → 更新掌握度
  → 重新诊断
  → 推荐路径发生合理变化
  → 查看推荐原因或 AI 解读
```

管理端至少能够稳定完成：

```text
登录
  → 查看统计概览
  → 查询/编辑知识点与前置关系
  → 查询/编辑题目与 Q 矩阵关系
  → 查看学生掌握度、诊断和答题记录
```

“页面能打开”“使用硬编码数据演示”“接口失败后静默显示假成功”均不属于完成。
