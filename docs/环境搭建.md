# 环境搭建指南

> 整合自各交付文档的零散部署信息（SQL Server 初始化、Neo4j 导入、后端启动、双前端启动）。
> 首次搭建按本页顺序执行即可。所有敏感配置一律走 `server/.env`，禁止提交到版本控制。

---

## 一、组件总览与初始化顺序

| # | 组件 | 用途 | 依赖 |
|---|------|------|------|
| 1 | SQL Server | 用户/题目/答题/诊断/社交数据（11 张表，`server/sql/init.sql`） | ODBC Driver 17 |
| 2 | Neo4j | 知识图谱（知识点 + 前置关系） | `kg-data/` CSV 数据 |
| 3 | FastAPI 后端 | 统一 API（`server/app/main.py`） | 上面两者 |
| 4 | 管理后台 admin | Vue 3 SPA | 后端 |
| 5 | 客户端 frontend | UniApp（H5 + 小程序） | 后端 |

## 二、SQL Server

1. 安装 SQL Server（开发者版即可），并安装 **ODBC Driver 17 for SQL Server**（`server/.env.example` 默认驱动名）。
2. 创建数据库（库名与配置一致，默认 `adaptive_learning`），在 SSMS 或 `sqlcmd` 中执行：
   ```bash
   sqlcmd -S localhost,1433 -U sa -P <密码> -i server/sql/init.sql
   ```
   > 脚本可重复执行（每张表前有 DROP 检查），会写入示例数据。
3. 注意：`init.sql` 示例用户的 `password_hash` 是占位假哈希，**不能直接登录**。真实账号通过后端 `POST /auth/register` 注册（学生）；管理员账号需手工向 `users` 表插入一条真实 bcrypt 哈希（可用 `python -c "import bcrypt; print(bcrypt.hashpw(b'密码', bcrypt.gensalt()).decode())"` 生成）。
4. 连接配置填到 `server/.env` 的 `SQLSERVER_HOST/PORT/USER/PASSWORD/DATABASE`（Windows 集成认证则设 `SQLSERVER_TRUSTED_CONNECTION=yes`）。

## 三、Neo4j

1. 本机实例已迁移到项目主目录：`E:\reasonix\creation\neo4j-chs-community-5.26.26-windows`，默认 `bolt://localhost:7687`，用户 `neo4j`。启动后确认 7687 端口监听；目录存在不等于服务已经启动。
2. 导入知识图谱示例数据（22 知识点 / 5 章节 / 31 条前置边，初中数学）：
   ```bash
   cd kg-data
   python scripts/import_knowledge_graph.py --force --password <neo4j密码>
   ```
   - 密码优先级：CLI `--password` > `server/.env` 的 `NEO4J_PASSWORD` > 空；
   - 不加 `--force` 为增量 MERGE（可重复执行不产生重复）；
   - 脚本内置 DFS 环检测，发现环会拒绝导入并报错退出。
3. 验证导入：
   ```bash
   python scripts/verify_import.py --password <neo4j密码>
   ```
   预期输出：Chapter 5 / KnowledgePoint 22 / BELONGS_TO 22 / PREREQUISITE 31。
4. 注意：`q_matrix` 与 `user_kp_mastery` 的 `knowledge_point_id` 必须与 Neo4j 节点 `id` 一致（跨库关联，无物理外键）。

## 四、后端（FastAPI）

```bash
cd server
# 1. 复制模板并填写真实连接信息
Copy-Item .env.example .env      # Linux: cp .env.example .env
# 2. 安装依赖
pip install -r requirements.txt
# 3. 跑测试（可选，268+ 用例全绿即可继续）
python -m pytest tests/ -v
# 4. 启动（必须在 server/ 目录下启动；.env 固定解析到 server/.env）
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

- **SECRET_KEY**：启动时若提示仍为占位符，请生成强随机密钥填入 `.env`：`python -c "import secrets; print(secrets.token_hex(32))"`，否则 JWT 可被伪造。
- **CORS**：`.env` 的 `CORS_ALLOW_ORIGINS` 默认 `*`（开发）；生产配置具体前端域名（配置具体来源时自动启用凭证）。
- **速率限制**：`RATE_LIMIT_*` 四项控制登录/注册限速（内存实现，重启清零；多实例部署需换共享存储）。
- 验证：`GET http://localhost:8000/health`（neo4j/sqlserver 布尔状态）、`GET http://localhost:8000/docs`（Swagger）。

## 五、管理后台（admin）

```bash
cd admin
npm install
npm run dev        # http://localhost:3000，Vite 将 /api/* 与 /auth/* 代理到 http://localhost:8000
npm run build      # 生产构建 → dist/（生产用 nginx 反代 /api 与 /auth）
```

- 登录账号为后端 `users` 表中 `role='admin'` 的用户（初始化示例 `admin_wang` 为假哈希，需先按第二节第 3 点重建真实哈希）。
- 前端 axios 已统一处理 `{code, data, message}`，HTTP 401 自动跳登录。

## 八、常见问题

| 现象 | 排查 |
|------|------|
| 后端启动报 pyodbc 找不到驱动 | 安装 "ODBC Driver 17 for SQL Server"（或改 `.env` 的 `SQLSERVER_DRIVER`） |
| `/health` 返回 `sqlserver: false` | 检查 1433 端口、账号密码、库名 `adaptive_learning` 是否已建 |
| `/health` 返回 `neo4j: false` | 检查 7687 端口监听与 `NEO4J_PASSWORD` |
| 登录提示"用户名或密码错误" | 示例数据用户是假哈希；先注册新学生或重建管理员哈希 |
| 管理接口返回 401/403 | 管理接口已启用鉴权：需管理员 Token；学生 Token 只能访问学员端 |
| 请求返回 429 | 触发登录/注册限速，等窗口滑动后重试（阈值见 `.env` 的 `RATE_LIMIT_*`） |
| 前端联调 CORS 报错 | 开发用 Vite 代理（已配）；直连时把前端地址加进 `CORS_ALLOW_ORIGINS` |
