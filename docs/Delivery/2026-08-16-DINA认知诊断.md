```json

    "data": {
```

## 三、算法说明（DINA 模型）

### 3.1 模型

- 知识点数 K = Q 矩阵列数；学生掌握模式 α ∈ {0,1}^K；
- 题目 j 的理想作答 η_j = ∏_k α_k^{q_jk}（掌握考察的**全部**知识点才「会做」，AND 门）；
- 作答概率：P(X_j=1|α) = (1-s_j)^{η_j} · g_j^{1-η_j}；
  - **失误率 s_j**：已掌握全部考察知识点仍答错的概率；
  - **猜测率 g_j**：未掌握任一考察知识点仍答对的概率。

### 3.2 EM 估计题目参数（de la Torre, 2009）

以全量 `answer_records`（全体学生）为样本：

- **E 步**：P(α|X_i) ∝ P(α)·∏_j P(X_ij|α)，类先验 P(α) 按独立属性构造，边际取全体学生掌握概率均值（自 `user_kp_mastery`，无数据 0.5）；
- **M 步**：ŝ_j = 期望错答数/期望会做人数；ĝ_j = 期望猜对数/期望不会做人数（后验加权）；
- **收敛准则**（总则第七条）：参数最大变化 < `DINA_EM_CONVERGENCE_THRESHOLD`(0.001) 即收敛，上限 `DINA_EM_MAX_ITERATIONS`(500)；s/g 初始值取 `DINA_S_INITIAL`/`DINA_G_INITIAL`(0.2)，并钳制在 [0.1, 0.3]；
- 缺失数据天然支持（学生只对作答过的题目求和）；无人作答的题目保持初始参数（分母保护）。

**E 步按学生自适应**（纯 Python 下的规模工程处理）：

1. **精确全枚举**：在学生「作答涉及知识点」子空间枚举 2^m 个模式（m = 该生作答题目涉及的知识点数）。未涉及知识点无证据、后验=先验，子空间枚举与全空间推断数学等价；2^m ≤ 1024（m ≤ 10）时使用——覆盖绝大多数真实场景（含 demo 数据）；
2. **置信传播 loopy BP 兜底**：m 超过上限时，在「知识点变量 × 题目因子」因子图上运行阻尼 sum-product。因子图为树时收敛于**精确**后验，含环时为标准 loopy BP 近似（偏差远小于平均场近似），仅在精确枚举不可行时兜底。

> 说明：曾实现平均场近似作为兜底，实测其在多知识点题目上存在严重系统性偏差（无法表达「解释消除」导致 g 塌缩），已替换为置信传播并保留测试佐证。

### 3.3 贝叶斯后验推断 α

题目参数固定后，对学生作答 X 计算 P(α_k=1|X)：

- **先验 = 上一轮 α**（总则第七条）：取该学生 `user_kp_mastery` 快照，无记录知识点取中性先验 0.5；
- 推断算法同样按 2^m 自适应选择精确枚举 / BP；
- 输出为后验边际概率（软掌握概率，非硬 0/1 分类），与契约示例一致。

### 3.4 数据流（与数据库设计「三、数据流向总览」一致）

```
q_matrix ──┐
           ├──→ EM 估计 s/g（全样本 answer_records + 全学生掌握均值作先验）
answer_records ──┘
                    │
user_kp_mastery（上一轮 α 作先验）──→ 贝叶斯后验推断 α ──┬──→ diagnosis_sessions（插入一条）
                                                        └──→ user_kp_mastery（upsert 有证据知识点）
```

## 四、关键设计决策（标注，待人工确认）

1. **EM 样本范围**：题目参数用**全量学生**作答估计（de la Torre 2009 的惯例，单生样本 s/g 不可识别），学生 α 用**本人全部历史**作答推断（与契约示例「两次诊断题量递增 20→25」一致）。
2. **先验与证据关系**：总则要求「上一轮 α 作先验」，而历史作答已含在上一轮 α 中，故后验存在证据部分重复累计（方法学上更优的做法是「只取上次诊断后的新记录 + 旧 α 作先验」）。**本实现严格按总则执行**（项目宪法优先），此权衡已标注。
3. **α 向量口径**：「维度 = 知识点总数」按 **Q 矩阵内知识点总数**理解（无题目关联的知识点不可识别，无法出现在 DINA 属性空间中）。
4. **user_kp_mastery 更新范围**：仅更新有作答证据的知识点（掌握概率=后验，做题数/正确数自 answer_records×q_matrix 重算）；无证据知识点保持「无记录 = not_started」语义，避免 0.5 假数据污染学员端状态展示。
5. **新增业务码 40002**：契约未定义「答题记录不足」的码值，按总则分段规则（40000-40999 客户端错误）取 40002，未占用已有码。
