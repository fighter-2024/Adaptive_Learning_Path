## 二、接口与契约对照（严格逐字段核对）

### GET /api/student/path

| 契约要求 | 实现 |
|----------|------|
| 参数 `target_kp_id`（可选，不传推荐全局下一步） | `Query(None, max_length=32)` |
| 参数 `count`（可选，默认 5） | `Query(5, ge=1, le=50)`，Pydantic 校验（总则：不手写校验） |
| `data.target: {id, name}` | `PathTarget`；全局模式为 `null` |
| `data.steps[].order` | 从 1 开始递增 |
| `data.steps[].knowledge_point: {id, name}` | `PathKnowledgePoint` |
| `data.steps[].reason` | 每步必有中文理由（文案对照契约示例） |
| `data.steps[].difficulty / estimated_time / mastery_probability` | 图谱属性 + SQL Server 掌握快照；无诊断数据为 `null` |
| 统一响应 `{code, data, message}` | `ApiResponse[LearningPathData]`，成功 `code=0` |

错误映射：目标不存在 → `40400`「目标知识点不存在」；图谱存在环 → `50002`「知识图谱前置关系存在环路，请联系管理员修复」；Neo4j 不可用 → `50002`「图数据库异常，请稍后重试」。

### GET /api/student/path/explain

| 契约要求 | 实现 |
|----------|------|
| `data.explanation`（字符串） | `PathExplainData`；大模型失败时降级为规则解释，接口始终返回非空内容 |
| 参数与 /path 一致 | 同 `target_kp_id` + `count`，保证两次调用解释与路径一致 |

## 三、算法实现说明

### 1. 拓扑加载（Neo4j，总则第六条职责划分）

`_db_load_topology()` 一次查询取回全部 `KnowledgePoint` 节点属性与
`PREREQUISITE` 边（知识点为百级规模，单次加载可行），在内存中构建
前置映射（后继 → 前置列表）。

### 2. 拓扑排序（前置关系不违反）

`topological_sort()`（Kahn 算法，纯函数）对候选子图排序：
- 目标模式只对「能到达目标」的子图排序（BFS 反向计算距离，不可达节点排除）；
- 检测到环抛 `KnowledgeGraphCycleError`，router 映射为 50002；
- 同批入度 0 节点按原始顺序出队，结果稳定可复现。

### 3. 多指标贪心打分（四项指标全覆盖）

```
score = 0.40·(1-掌握概率)     ← 距目标相关：弱项优先补（无数据按 p=0）
      + 0.20·(1-难度)         ← 难度越低越优先（循序渐进）
      + 0.15·(1-时长/最长时长) ← 预估耗时越短越优先
      + 0.25·(1-距目标/最远距) ← 距目标越近越优先（仅目标模式）
```

- 掌握概率来自 SQL Server `user_kp_mastery`（总则第六条：DINA 诊断结果存关系库）；
- 已掌握（≥0.8，与契约 2.1 阈值一致）的知识点不进入推荐；
- 权重为模块常量，业务可调（改动需同步测试）。

### 4. 贪心选择（关键约束）

每一步只在「前置已满足」的候选里选分最高者——前置已满足指：
前置已掌握（≥0.8）**或已入选当前路径**。因此产出序列天然满足拓扑序，
前置关系不被违反，且不会出现「路径里缺前置」的断链。

### 5. reason 生成（对照契约示例文案）

- 目标知识点 → 「这是你的目标知识点，建议集中精力学习」
- 有前置已入路径但未掌握 → 「前置知识「XX」尚未完全掌握，需重点学习」（对照契约示例步骤 2）
- 无数据 → 「尚未开始学习，建议从基础概念入手」
- p<0.4 → 「当前掌握 X%，基础薄弱，需重点学习」
- 0.4≤p<0.8 → 「当前掌握 X%，巩固后可进入下一阶段」（对照契约示例步骤 1）
- 距目标 1 跳 → 追加「，是目标「XX」的直接前置」

## 四、AI 解释与降级（总则第八章逐条落实）

| 总则要求 | 实现 |
|----------|------|
| 所有大模型调用走统一 service 封装 | `services/llm_service.py::chat_completion()`，业务不直接发 HTTP |
| 超时默认 30s | `settings.LLM_TIMEOUT`（默认 30） |
| 重试最多 2 次 | 首次 + 2 次重试，共 3 次尝试 |
| Prompt 模板单独管理 | `config/prompts.py`（零依赖，只拼字符串） |
| 返回内容基本校验 | 非空校验 + 长度上限（封装层 8000 字符截断；解释层 2000 字符超限即降级） |
| 失败返回降级内容，不阻塞业务 | 未配置密钥/超时/异常 → `None` → `build_rule_based_explanation()` 规则解释；解释接口永不因 LLM 失败而报错 |
| 禁止硬编码密钥 | 全部走 `settings.LLM_API_KEY / LLM_API_BASE / LLM_MODEL`（.env） |

说明：DeepSeek 与通义千问均走 OpenAI 兼容 `/chat/completions` 接口，
`LLM_API_BASE` 填 `https://api.deepseek.com` 或
`https://dashscope.aliyuncs.com/compatible-mode/v1`。
