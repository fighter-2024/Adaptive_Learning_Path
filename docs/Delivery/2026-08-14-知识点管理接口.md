## 二、接口清单（对照 docs/API契约文档.md 1.1）

| 接口 | 说明 | 关键行为 |
|------|------|----------|
| `GET /api/admin/knowledge-points` | 分页查询 + 按章节筛选 + 按名称模糊搜索 | `page`/`page_size`/`chapter_id`/`keyword`；响应 `{list,total,page,page_size}`；列表项含契约全部字段（含 `prerequisite_count`/`question_count`/`created_at`） |
| `GET /api/admin/knowledge-points/{id}` | 单个详情 | 含 `prerequisites`（前置）与 `dependents`（后继） |
| `POST /api/admin/knowledge-points` | 新增 | 服务端生成 ID（`kp_xxxxxxxx`）；校验章节存在；建立 `BELONGS_TO` |
| `PUT /api/admin/knowledge-points/{id}` | 编辑 | 请求体同 POST；换章节时重建 `BELONGS_TO` |
| `DELETE /api/admin/knowledge-points/{id}` | 删除 | 删除前检查依赖，被依赖时返回契约规定的 `{"code": 40001, "message": "该知识点被 N 个知识点依赖，无法删除"}` |
| `POST /api/admin/knowledge-points/{id}/prerequisites` | 全量替换前置 | 传什么就是什么（不追加），空列表=清空；校验存在性、自引用、全图环检测，事务内原子执行 |

错误码映射：知识点/章节不存在→`40400`；参数/业务校验失败→`40000`；被依赖无法删除→`40001`（契约指定）；Neo4j 异常→`50002`（不暴露堆栈）。

## 三、实现要点与设计决策

1. **图谱结构对齐导入脚本**：`KnowledgePoint{id,name,description,chapter_id,difficulty,estimated_time,sort_order,created_at}`、`Chapter`、`(:KnowledgePoint)-[:BELONGS_TO]->(:Chapter)`、`(前置)-[:PREREQUISITE]->(后继)`，与 `kg-data/scripts/import_knowledge_graph.py` 完全一致，历史导入数据可直接被接口读取。
2. **数据库职责划分（总则第六条）**：图谱拓扑（节点、前置关系、`prerequisite_count`）走 Neo4j；`question_count` 从 SQL Server `q_matrix` 表聚合。**SQL Server 不可用时 `question_count` 降级为 0 并记 warning 日志，不阻塞列表查询**——设计取舍：列表接口不应因附属统计字段失败而整体不可用（当时 SQL Server 未运行，未验证真实计数路径，见「六、遗留事项」）。
3. **`created_at`**：新创建/编辑的知识点写入 ISO 8601 格式（`2026-08-14T22:48:40`）；历史 CSV 导入的节点无此属性，接口如实返回 `null`（Pydantic `Optional[str]`），未编造数据。
4. **前置替换的完整校验**：前置知识点必须全部存在；禁止以自身为前置；DFS 三色标记环检测覆盖「现有全图边（排除目标旧入边）+ 新入边」，发现环给出环路径（如 `kp_002 → kp_001 → kp_002`）并拒绝，整个替换在 Neo4j 写事务内原子执行（校验失败自动回滚，实测回滚后原前置保持不变）。
5. **异步规范（总则）**：接口全部 `async def`；同步 Neo4j/SQL Server 操作经 `asyncio.to_thread` 放入线程池；写操作用 `session.execute_write` 保证事务性。Service 层不接触 HTTP 对象，业务异常由 router 映射为业务码。
6. **参数校验（总则）**：分页参数用 FastAPI `Query(ge/le)` 约束（`page≥1`、`page_size 1~100`）；请求体全部 Pydantic 模型（`difficulty 0~1`、`estimated_time 1~600`）；新增 422 全局处理器，使校验失败也返回统一 `{code:40000, data:null, message}`，不再暴露 FastAPI 默认 `detail` 结构。
7. **不引入新依赖**：仅使用已有 `neo4j`/`pyodbc`/标准库。

## 六、遗留事项与注意

1. **`question_count` 真实值未验证**：验证时 SQL Server 未运行（本机 1433 未监听），走的是降级路径（返回 0）。SQL Server 启动并执行 `server/sql/init.sql` 后，`q_matrix` 的计数逻辑（`GROUP BY knowledge_point_id`）建议按本文档「四」的集成验证方式复核一次。
2. **本机 Neo4j**：`E:\neo4j\neo4j-chs-community-5.26.26-windows` 存在但验证时未监听 7687，故用 Docker 验证。切回本机实例只需在 `server/.env` 配置 `NEO4J_URI/NEO4J_USER/NEO4J_PASSWORD`（当前 `server/.env` 尚未创建，可参考 `.env.example`）。
3. **`created_at` 为 null**：历史 CSV 导入的知识点无 `created_at` 属性，接口如实返回 `null`；后续新建/编辑的数据均有值。如需历史数据补齐时间，可在导入脚本中增加该属性。
4. **ID 风格**：新知识点 ID 为 `kp_{8位uuid}`（如 `kp_c9715c52`），与现有 `stu_/adm_` 风格一致；CSV 历史数据为 `kp_001` 序号风格，两者并存不冲突。
