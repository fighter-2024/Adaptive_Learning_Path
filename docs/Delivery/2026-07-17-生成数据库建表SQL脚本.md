# 生成数据库建表 SQL 脚本

## 交付内容

生成 `server/sql/init.sql`，包含 SQL Server 的 11 张业务表完整建表脚本。

## 文件清单

| 文件 | 说明 |
|------|------|
| `server/sql/init.sql` | 数据库初始化脚本（~450 行） |

## 覆盖范围

根据 `docs/数据库设计.md` 第 1.1–1.11 节定义，生成以下 11 张表：

| # | 表名 | 职责 | 示例数据条数 |
|---|------|------|------------|
| 1 | `users` | 用户（学生/管理员） | 3 |
| 2 | `chapters` | 章节（支持多级父子） | 3 |
| 3 | `questions` | 题目（单选/多选/判断） | 3 |
| 4 | `q_matrix` | Q 矩阵（题目-知识点关联） | 3 |
| 5 | `answer_records` | 答题记录 | 3 |
| 6 | `diagnosis_sessions` | DINA 诊断会话快照 | 3 |
| 7 | `user_kp_mastery` | 用户知识点掌握快照 | 3 |
| 8 | `check_ins` | 每日打卡 | 3 |
| 9 | `achievements` | 成就定义 | 4 |
| 10 | `user_achievements` | 用户成就记录 | 3 |
| 11 | `weekly_reports` | AI 周报 | 2 |

## 约束与索引

- **主键**：每表 INT IDENTITY 自增主键
- **唯一约束**：13 个（覆盖所有业务 ID 列及文档标注的复合 UK）
- **CHECK 约束**：5 个（role、type、difficulty、condition_type、correct_rate）
- **非聚集索引**：3 个
  - `answer_records (user_id, created_at)`
  - `answer_records (question_id)`
  - `diagnosis_sessions (user_id, diagnosed_at DESC)`
- **默认值**：`created_at` / `generated_at` / `diagnosed_at` → `GETDATE()`；`is_active` → `1`

## 外键关系

所有外键关系以注释形式标注（不创建物理外键），脚本末尾附有完整的外键关系一览表，包含 SQL Server 内部关联和 SQL Server ↔ Neo4j 跨数据库关联。

## 设计决策

1. **不创建物理外键**：文档要求"外键关系标注在注释中"，且跨数据库（Neo4j）无法创建物理外键。
2. **额外 CHECK 约束**：对 `role`、`type`、`difficulty`、`condition_type`、`correct_rate` 添加了 CHECK 约束，属于合理增强。
3. **`created_at` 统一默认值**：设计文档中部分 `created_at` 未标注 DEFAULT，统一加了 `DEFAULT GETDATE()`。
4. **可重复执行**：每张表前有 `IF OBJECT_ID ... DROP TABLE`，脚本可安全重复执行。
