## 可复现响应证据（脱敏）

取题响应字段集合固定为：

```text
id, content, type, difficulty, options
answer_or_explanation_exposed=false
```

判题服务的自动化证据使用同一知识点的中性先验：

```text
正确作答：POST /api/student/submit-answer {question_id, student_answer, time_spent}
响应：code=0, correct=true, mastery_change={kp: {before: 0.5, after: 0.8}}

错误作答：POST /api/student/submit-answer {question_id, student_answer, time_spent}
响应：code=0, correct=false, mastery_change={kp: {before: 0.8, after: 0.5}}
```

专项测试还验证了：同一批次先写答题记录、后写掌握快照时若第二步失败，事务执行 rollback 且不执行 commit；批量中不存在题目只写该项 `error`，不阻塞其他成功题。

## 真实双库实证

在已配置证书的 SQL Server 上，以本轮代码启动隔离 API 端口，使用唯一临时学生账号完成真实联调；账号、Token 和密码未写入文档。验收后按该账号精确删除答题记录、掌握快照和用户行，清理命令返回 `cleanup_complete=true`。

### 1. 正式取题响应脱敏

`GET /api/student/questions?knowledge_point_id=kp_001&count=10` 返回 `code=0`，题目字段集合为：

```text
content, difficulty, id, options, type
answer=false
explanation=false
```

### 2. 正确与错误作答

```text
POST /api/student/submit-answer
{question_id: "q_001", student_answer: "A", time_spent: 12}
→ code=0, correct=true
→ kp_001: 0.5 → 0.8；kp_002: 0.5 → 0.8

POST /api/student/submit-answer
{question_id: "q_001", student_answer: "B", time_spent: 8}
→ code=0, correct=false
→ kp_001: 0.8 → 0.5；kp_002: 0.8 → 0.5
```

### 3. SQL Server 前后查询

| 时点 | answer_records | kp_001 掌握快照 |
|---|---:|---|
| 作答前 | 0 | null |
| 两次作答后 | 2 | `mastery_probability=0.5, questions_done=2, correct_count=1` |

随后使用 `exclude_done=true` 重新取题，`q_001` 不再出现在列表中，证明服务端基于真实答题记录筛选。
