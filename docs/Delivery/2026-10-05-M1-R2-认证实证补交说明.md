## 3. 失效 Token 与权限实证

通过隔离的临时 `8001/8082` 环境验证，不修改主后端 `8000` 的密钥或有效期：

- 先用临时签名密钥 A 完成学生登录，再以临时签名密钥 B 重启隔离后端；刷新时旧 Token 被判定为签名无效，前端自动清理会话并回到登录页，显示“登录凭证无效或已过期，请重新登录”。
- 使用 `JWT_EXPIRE_MINUTES=0` 的隔离后端签发立即过期 Token；登录后的 `/auth/me` 返回 401，前端自动清理会话并显示同一失效提示。
- 隔离环境验证结束后，临时 `8001/8082` 服务已关闭。

后端脱敏接口实证：

| 场景 | HTTP | 业务码 | 消息 |
|---|---:|---:|---|
| student Token 请求管理接口 | 403 | `40101` | 仅管理员可访问此接口 |
| admin Token 请求学生接口 | 403 | `40101` | 仅学生可访问此接口 |
| 过期 Token 请求 `/auth/me` | 401 | `40100` | 登录凭证无效或已过期，请重新登录 |
| 伪造 Token 请求 `/auth/me` | 401 | `40100` | 登录凭证无效或已过期，请重新登录 |
