## 二、脚本功能

### CLI 参数

```
python scripts/import_knowledge_graph.py --force              # 清空后全量导入
python scripts/import_knowledge_graph.py                      # 增量 MERGE（保留已有数据）
python scripts/import_knowledge_graph.py --password <pwd>     # 指定密码
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--force` | 关闭 | 导入前 `DETACH DELETE` 清空全部节点和关系 |
| `--uri` | `.env` → `bolt://localhost:7687` | Neo4j bolt 连接地址 |
| `--user` | `.env` → `neo4j` | 用户名 |
| `--password` | `.env` → NEO4J_PASSWORD | 密码（优先级: CLI > .env > 空） |
| `--data-dir` | `kg-data/data/knowledge_points/` | CSV 数据目录 |

### 导入流程

1. 加载 `.env` 配置（`server/.env`）
2. 连接 Neo4j，验证连通性
3. `--force` 模式下执行 `MATCH (n) DETACH DELETE n`
4. 读取三个 CSV 文件
5. 依次导入：
   - **Chapter 节点** — `MERGE`，按 `id` 去重
   - **KnowledgePoint 节点** — `MERGE`，按 `id` 去重，属性含 `name`/`description`/`difficulty`/`estimated_time`/`chapter_id`/`sort_order`
   - **BELONGS_TO 关系** — `(KnowledgePoint)-[:BELONGS_TO]->(Chapter)`，`MERGE` 去重
   - **PREREQUISITE 关系** — `(前置)-[:PREREQUISITE]->(后继)`，`MERGE` 去重
6. 环检测（DFS 三色标记法），发现环则拒绝创建并报错退出
7. 输出统计：各类节点数、关系数、耗时

## 五、设计决策与注意事项

1. **连接密码优先级**：CLI `--password` > `.env` 的 `NEO4J_PASSWORD` > 空字符串。任何 Neo4j 实例密码都不得写入文档、日志或命令记录；优先使用受控环境变量或密钥管理器注入，必要时通过安全交互方式提供。

如凭证曾暴露，应在受控实例执行交互式轮换：

```powershell
python kg-data/scripts/rotate_neo4j_password.py --write-env --confirm
```
2. **Chapter 节点**：当前脚本在 Neo4j 中创建 Chapter 节点并建立 BELONGS_TO 关系。将来如果章节管理完全走 SQL Server，可移除 Chapter 导入，仅保留 `chapter_id` 属性。
3. **去重策略**：全部使用 Cypher `MERGE`，重复运行不会产生重复数据，适合增量更新。
4. **环检测**：在创建 PREREQUISITE 关系**之前**独立运行 DFS 环检测，发现环立即拒绝并列出环路径，不写入 Neo4j。
5. **符合项目规范**：
   - ✅ 文件放 `kg-data/scripts/`，符合目录结构
   - ✅ 使用 `logging` 而非 `print`
   - ✅ 标识符英文、注释中文，函数有 docstring
   - ✅ 类型注解完善
   - ✅ 凭据不硬编码，支持 .env + CLI
   - ✅ 不引入新依赖（仅使用已有的 `neo4j` 驱动 + 标准库 `argparse`/`csv`/`pathlib`）
6. **验证脚本** `verify_import.py` 已重写为合规版本：CLI/.env 读取连接参数（不硬编码密码），使用 `logging` 模块，增加 Neo4j 侧环检测和断言式验证。
