# AI 开发总则

> **每个 AI 代理会话开始干活前，必须先读取本文件。**
> 本文件定义项目边界、技术约束和质量标准，所有代理必须遵守。

---

## 一、项目是什么

**基于知识图谱的自适应学习路径规划与社交激励系统**（省级大创项目）。

核心能力：
- 知识图谱存储知识点及其前置依赖关系
- DINA 认知诊断模型推断学生知识掌握状态
- 拓扑排序 + 多指标贪心推荐个性化学习路径
- AI 辅助：诊断解读、错题归因、周报生成
- 轻量社交激励：排行榜、打卡、成就

---

## 二、技术栈（不可随意变更）

| 层 | 技术 | 备注 |
|------|------|------|
| 后端框架 | **Python FastAPI** | 异步优先 |
| 图数据库 | **Neo4j** | 知识图谱专用 |
| 关系数据库 | **SQL Server** | 用户/题目/答题记录 |
| 管理后台前端 | **Vue 3 + Vite + Element Plus** | SPA，浏览器运行 |
| 客户端前端 | **UniApp（Vue 3）+ uni-ui** | H5 + 微信小程序 |
| AI 大模型 | DeepSeek / 通义千问 | 通过 API 调用，不本地部署 |
| 配置管理 | **pydantic-settings + .env** | 禁止硬编码密钥 |
| 包管理 | **npm**（前端）、**pip**（后端） | 不引入新的包管理器 |

## 三、项目目录结构（不可随意打破）

```
creation/
├── docs/                     # 文档：申报书/API文档/数据库设计/会议记录
├── kg-data/                  # 知识图谱数据 & 构建脚本
│   ├── data/                 #   原始资料/知识点/题库
│   ├── scripts/              #   数据清洗 & Neo4j 导入脚本
│   └── output/               #   构建好的图谱导出
├── server/                   # FastAPI 后端
│   └── app/
│       ├── main.py           #   入口
│       ├── routers/          #   API 路由（admin/ 和 student/）
│       ├── models/           #   Pydantic 数据模型
│       ├── services/         #   业务逻辑：DINA/路径规划/社交/AI解释
│       ├── db/               #   Neo4j + SQL Server 连接
│       └── config/           #   配置（pydantic-settings）

├── frontend/                 # UniApp 客户端前端
├── algorithm/                # 算法实验（Jupyter Notebook）
└── AGENTS.md                 #   项目元信息
```

**规则**：
- 新增文件必须在对应目录，不得随意创建顶层目录
- 路由文件放 `routers/`，业务逻辑放 `services/`，不能混放
- Pydantic model 放 `models/`，不与 SQLAlchemy/ORM model 混淆

## 四、API 规范（强制）

现行唯一接口契约：`docs/改进计划与任务卡/API契约文档-v2.md`。旧 `docs/API契约文档.md` 已冻结，仅作历史追溯。

### 响应格式

```json
{
    "code": 0,
    "data": ...,
    "message": ""
}
```

### 状态码分段

| 范围 | 含义 |
|------|------|
| `0` | 成功 |
| `40000 - 40999` | 客户端错误（参数校验、权限） |
| `50000 - 50999` | 服务端错误 |
| `60000 - 60999` | 第三方服务异常 |

### 路由前缀

```
/api/admin/*      →  管理后台接口
/api/student/*    →  学员端接口
```

### 分页格式

```json
{
    "code": 0,
    "data": {
        "list": [...],
        "total": 42,
        "page": 1,
        "page_size": 20
    },
    "message": ""
}
```

### 其他规则

- HTTP 方法语义：GET 查询、POST 创建、PUT 更新、DELETE 删除
- 所有接口参数用 Pydantic model 校验，不手写校验逻辑
- 错误 message 必须对用户可读，不暴露内部异常堆栈

## 五、代码规范

### 通用

- **标识符用英文**，注释用中文
- 函数/类必须有 docstring
- 禁止 `print` 调试，用 `logging` 模块
- 禁止硬编码任何密钥、密码、连接串，一律走 `.env`

### Python 后端

- 类型注解必须写（函数参数和返回值）
- 异步接口用 `async def`
- Service 层不直接接触 HTTP 请求对象（Request/Response），只处理业务数据
- 算法先在 `algorithm/notebooks/` 验证，成熟后迁移到 `services/`

### Vue / UniApp 前端

- 用 `<script setup>` 语法
- API 调用统一经过封装的 request 工具，不在组件里直接写 axios/uni.request
- 状态管理用 Pinia（Vue 3）
- UniApp 组件用 `<view>` / `<text>`，不用 HTML 标签

## 六、数据库职责划分

| 数据类型 | 存储位置 | 说明 |
|------|------|------|
| 知识点节点 + 前置关系 | **Neo4j** | 图的天然优势 |
| 用户信息 | **SQL Server** | 结构化数据 |
| 题目 + 选项 + 答案 | **SQL Server** | 结构化数据 |
| Q矩阵（题目-知识点映射） | **SQL Server** | 关联表 |
| 答题记录 | **SQL Server** | 每条记录关联 user + question |
| DINA 诊断结果 | **SQL Server** | α 向量序列化存储 |
| 社交数据（打卡/成就/好友） | **SQL Server** | 结构化数据 |

**禁止**：把用户数据、答题记录存 Neo4j；把图谱拓扑关系存 SQL Server。

---

## 七、DINA 认知诊断约束

- Q矩阵每个题目至少对应一个知识点
- EM 算法收敛阈值：参数变化 < 0.001 或最大迭代 500 次
- 学生 α 向量维度 = 知识点总数
- 失误率 s 和猜测率 g 的初始值范围：[0.1, 0.3]
- 贝叶斯后验推断使用上一轮 α 作为先验
- 纯 Python 实现，不依赖 scikit-learn / PyTorch 等 ML 框架

---

## 八、AI 大模型调用规范

- 所有大模型调用走统一的 service 封装，不散落在各处
- 必须设置超时（默认 30s）和重试（最多 2 次）
- Prompt 模板单独管理（放 config 或独立文件），不硬编码在业务逻辑里
- 大模型返回内容必须做基本校验（非空、长度合理），防止异常输出污染前端
- 调用失败时返回降级内容，不阻塞业务流程
